## 0. 结论先说：它们不是"我们的引擎"，是三种不同的工具

`割不割` 的产物是**单文件 H5、无后端、原生 JS**（`dist` 250 KB）。
而这里的承重仓库全是 **Python / C++ / Rust / Java / Scala** ——
**没有一个能在浏览器里跑**（唯一含 JS 的是 `otree-double-auction`，那是课堂问卷框架，要 Python 服务端）。

所以正确定位是**三种角色**，不是"换引擎"：

| 角色 | 做法 | 产出 | 价值 |
|---|---|---|---|
| **参考实现** | 读算法 → 翻译成 JS | 撮合、库存控制、削仓、追保 | 省设计时间 |
| **离线校准器** | 跑 Python ABM | 把我们的常数从"拍脑袋"变成"测出来" | ⭐ **最高** |
| **验证器** | 用它们的指标量我们的引擎 | Roll / Amihud / markout 基准 | 防自欺 |

**为什么"离线校准"最重要**：`docs/13` 里那三个旋钮（冲击 λ、`maintRatio`、收货商的库存系数）
**目前全是经验值，没有任何实测依据**。这批库的价值就在于给出**实测区间**。

## 1. 立刻可用的两批件（已精读）

### 1.1 `strategies/adverse_selection.py` → 一批**可以直接用的数字**

它是**测量模块**，不是策略。给的是做市/微观结构的**行业标准指标**：

| 件 | 内容 | 对我们的用法 |
|---|---|---|
| **markout 地平线** | `(5, 15, 30, 60, 300)` 秒 | 衡量"这笔成交之后价格往哪走"的标准窗口 |
| **有效价差** | `(成交价 − 中间价)/中间价 × 1e4 × 方向` | 做市商**报价那一瞬间**赚的 |
| **实现价差**（在 h 秒后） | `方向 × (成交价 − h 后中间价)/中间价 × 1e4` | 他**真正留下**的 |
| **价差分解** | **价格冲击 = 有效价差 − 实现价差** | ⭐「**你赚的是差价，还是被信息砸了**」的严格定义 |
| **逆向选择率** | 60 秒 markout 为负的成交**占比** | ⭐ **一个标量**，量化"这股流量有多毒" |
| **Roll (1984)** | `s = 2√(max(0, −cov(ΔPₜ, ΔPₜ₋₁)))` | ⭐ 只靠**成交 tick** 就能反推价差 |
| **Amihud (2002)** | `\|rₜ\| / volumeₜ`；分档见下 | 流动性/冲击的实测量 |

**Amihud 现成分档阈值**（拿来就能当我们的市场状态）：

| 阈值 | 状态 |
|---|---|
| `< 1e-7` | LIQUID |
| `< 1e-6` | NORMAL |
| `< 1e-5` | ILLIQUID |
| `≥ 1e-5` | EXTREMELY_ILLIQUID |

**⭐ 其中 Roll 那条对我们直接可用，而且解决了一个设计难题**：

> **收货商不该"知道"行情 —— 他应该用 Roll / Amihud 从成交记录里自己估出来。**

这样 `docs/13 §17.1` 那条症状「**你一拿情报就去找他，他立刻把价往下调**」
就有了**机械的、非作弊的**实现：他**不是偷看玩家的牌**，而是**从成交量序列里测出了信息毒性**
（逆向选择率上升 → 他降温/撤价）。**玩家看到的仍然是现象，但底下是真规则。**

### 1.2 `engine/central_risk_manager.py` → 一条**该抄的规则** + 一个**必须连修复一起抄的陷阱**

⚠️ **先注意它的定位**：这是**单公司内部风控**，**不是市场级清算引擎**。
我们要的「清算瀑布」它**没有**（`README` 说这点得自己设计，是对的）。

| 件 | 内容 | 对我们的用法 |
|---|---|---|
| ⭐ **`_reduces_skew()` 永远放行** | 削仓时，**任何"减少敞口"的单子无条件通过** —— 不能因为限额卡住你的止损 | 追保期内，玩家的**减仓/卖货操作绝不能被卡** |
| **波动率缩放仓位** | `effective_max = max_net / max(1, vol/vol_baseline)`；TOXIC 再砍 50%、ILLIQUID 再砍 30% | 收货商的「**今日还收 N 单位**」应**随波动率收缩**，而不是固定值 |
| ⭐ **毒性成交 → 冷却** | `report_toxic_fill()` 给该策略设 `toxicity_cooldown_s`（默认 60s） | 「他一有消息就压价」的机制原型：**不是改价，是降温/暂停** |
| **硬熔断** | 回撤超 `max_drawdown_limit` 或单日亏损超限 → **HALT**，全策略停单，需人工 `unhalt()` | 我们的"债主上门"可以有一档**强制停手** |
| ⚠️ **陷阱（必须连修复一起抄）** | `recent_events()` 里留着真实 bug 的修复注释：`deque` **不支持切片**，`self._event_log[-n:]` **每次调用都抛 TypeError** → 必须先 `list()` 再切 | 抄这段时别把 bug 抄回来 |
