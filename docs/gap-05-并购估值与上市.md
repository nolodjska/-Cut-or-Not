## ① 现状证据

### 1.1 一句话结论

**收购、股价、市值、IPO —— 四样一个都没有。**
引擎里只有三样东西：① 一层「持仓」数据结构（`holdings[]`）；② 一条「破产 → 拍卖 → 土地 / 存货转手」的清算链路；③ 一套**单主体**净资产估值 `nav()`。
收购的**结果字段**（`navSnapshot` / `control`）已经埋好，但**全项目没有任何写入点**；「被收购」这件事在引擎里只能通过「对方破产、你去拍卖会接盘」间接发生，而且接的是**地和货**，不是**公司股权**。

> ⚠ 与 `docs/19 §4.16-D` 的原文一致地纠一次（`docs/gap-03` 已先纠过）：**代码里没有 `_a_buyland`**。
> 把这句话留在本报告里，是因为 §4.16-D 那句「引擎现在已经有 `_a_buyland`」**今天仍然挂在文档里**，任何按它去接并购的人都会先撞一次空。

### 1.4 缺口一句话

引擎把「玩家 = 持有多家公司的金融巨鳄」的**容器**放好了（`holdings[]`、`consolidated()`、`_bankrupt` 标记持仓），**但容器里能装的东西一样都还没有**：
没有把一家公司**买下来**的路径、没有**定价**它的报告、没有**股价 / 市值**的概念、没有任何**门槛 / 要约**。**另有一处记账陷阱**：`consolidated()` 的主控公司**不乘 `stake`**（`05-firm.js:5`），`docs/19 §4.12` 已把它点名成「卖股份 = 印钞」的根因。

## ② 现实依据（附来源）

| 现实规律 | 要点 | 来源 |
|---|---|---|
| **未上市估值三法** | **资产基础法**（净资产重置）/ **收益法**（未来现金流折现）/ **市场法**（可比公司倍数）。三法口径不同 ⇒ **天然不收敛到同一个点值** | 《资产评估执业准则——企业价值》；`docs/19 §4.11-A`（已定「三法各给一个数 ⇒ 报告天然给区间」） |
| **评估报告只给区间、不给点值** | 报告是「价值区间 + 基准日 + 有效期」，成交在区间里谈；报告可被对手质疑并要求复核 | `docs/19 §4.2 / §4.11-A`；`docs/20 §6`（做成玩法：两次评估给不同区间） |
| **报告有效期 = 自评估基准日起 1 年** | 现行执业准则：资产评估报告**有效期通常为自评估基准日起 1 年**，不得超期使用；破产清算项目可短于 1 年（6 个月） | 《资产评估执业准则——资产评估报告》口径转述：https://www.sohu.com/a/711598805_128612 ；https://ailegal.baidu.com/legalarticle/qadetail?id=131c685501937a260120 |
| **DLOM 流动性折价** | 非上市 / 受限股权要打「缺乏流通性折扣」；准则明确要求评估时**考虑控制权与流动性差异**（《资产评估执业准则—企业价值》第三十二条） | 金证资产评估《两种常见缺乏流动性折扣的测算方法研究》：https://www.jzvaluation.com/archives/411 |
| **控制权溢价 20~40%** | 买到 >50%（拿到说话权）时，通常要在市价 / 评估值上再加一笔控制权溢价 | `docs/19 §4.14-A`（「现实常见 20–40%，游戏内默认 30%」）；并购实务的通行区间 |
| **并购付款三选** | 现金对价 / **换股（股权置换）** / **分期 + 业绩对赌（earn-out）**；另有承债式、LBO、借壳 | `docs/19 §4.11-C`；分期+对赌案例：莎普爱思「剩余 30% 价款（三期各 10%）与 2026–2028 业绩承诺挂钩」 https://m.21jingji.com/article/20260324/herald/0fd5e0e3f0d119c414e1ec80da769911.html |

## ④ 设定草案（按现实补）

> 目标：把「估值 / 收购 / 上市」从**零**，补成一条**能被玩家自己算出来、且每一步都有现实对应**的链路。
> 全程守 `docs/19 §4.10`（身价口径）与 `docs/20 §0`（三个钱不同屏）。

### 4.1 估值：两套口径 + 未上市区间生成

**上市 vs 未上市是两套口径**（`docs/19 §4.2` 已定）：

| | 上市 | 未上市 |
|---|---|---|
| 定价 | **市值 = 股价 × 总股本** | **评估报告区间** `[Lo, Hi]` |
| 怎么知道 | 挂牌即公开 | 付费请评估师，**给区间不给点值**，有误差 |
| 流动性 | 高 | 低 ⇒ 变现要打 **DLOM** |

**未上市：三法各一个数 → 区间**（`docs/19 §4.11-A`）：

```
三法（都以 nav() 与公司账为基础，07-metrics.js 现成）：
  ① 资产基础法  V_a = nav(p) + 无形资产加成
       无形资产 = brand × brandValuePt + 隐蔽度(shell.cover) × coverValuePt     // docs/19 §4.2 明列“品牌/隐蔽度/牌照”
  ② 收益法      V_i = 年化可分配利润 / 资本化率 k
       年化可分配利润 ≈ (本季 realized + 利息 + 分红收得) − 地租 − 维持开支     // Demo 无利润表，用 m.realized 年化 + 库存毛利估计
       k 按公司类型：grow .14 · trade .16 · intel .18 · shell .20 · make .15 · fin .13
  ③ 市场法      V_m = 同 route 的可比公司净资产 × 行业倍数 m
       m（Demo 拍板）：grow 1.0 · trade 1.2 · intel 1.5 · shell 1.8 · make 1.3 · fin 1.1

区间生成（关键：报告给的是区间）：
   Lo = min(V_a, V_i, V_m) × (1 − e)
   Hi = max(V_a, V_i, V_m) × (1 + e)
   e = 评估师误差 ∈ [0.10, 0.25]，由**独立随机流** hash32(seed,'valuation') 决定
       ⇒ 同一份报告内 e 固定；**两次评估 e 不同 ⇒ 两次区间不同**（这是玩法，不是 bug，docs/19 §4.2 已定）
```

**上市：** 市值 = 股价 × 总股本（见 §4.6）。

### 4.2 有效期（按现实）

- 现实：报告有效期 **自基准日起 1 年**（破产清算类可短至 6 个月）。
- 游戏内映射：**`报告有效期 = 24 游戏小时（= 1 游戏日）`**。
  依据：`docs/06 §2` 定义「整局 = 72 游戏小时 = 3 游戏日」，即一整局 = 3「年」⇒ **1 游戏日 ≈ 1 年**（Demo 3 天 = 3 年）。
- 过期后果：报告标记 `expired`，**不能作为成交价依据**；UI 告急带提示（`docs/20 §1.1` 已把「评估报告过期」列入告急带来源）；重新评估要再付一次钱、再等一次。
- 完整赛季（`docs/11`）按同一比例放大。

### 4.3 溢价与折价（两个方向都要有）

| 方向 | 现实依据 | 游戏内默认 |
|---|---|---|
| **控制权溢价** | 买到 >50% 拿到说话权，现实 20–40% | **+30%**（可按人格浮动，`docs/19 §4.14-A`） |
| **DLOM 流动性折价** | 非上市 / 急于脱手 | **−15%~−30%**，急卖越狠折越多 |
| **无形资产加成** | 品牌 / 隐蔽度 / 牌照 | 见 §4.1 ①（加在资产基础法上） |

```
成家价（未上市，非急卖）= 报告区间中值 (Lo+Hi)/2 ×(1 + 控制权溢价 30%)
成家价（未上市，急卖）= 报告区间中值 ×(1 − DLOM)
        ⇒ 两个价不会同时用；「急卖要折价」是 UI 话术（docs/20 §6）
```

### 4.4 收购付款三选：对价算法与结算时机

`docs/19 §4.11-C` 已定主打三种。三种的**对价算法**与**结算时机**分别如下（这是本报告新增的可落地口径）：

**（1）现金对价**
```
应付 = 成家价（含控制权溢价）
结算时机：要约被接受 → **当场一次性**从买方 p.cash 扣；不足则拒绝或引导去钱庄（复用 _a_loan）
过户时机：扣款成功当帧，标的 holdings 并入买方（control = 持股比例）
```

**（2）换股（股权置换）**
```
对价 = 成家价；买方不出现金，而是按换股比例“印”给卖方买方自己的股份
  换股比例 R = 成家价 / 买方每股估值
结算时机：签约当帧
  ① 买方 totalShares += R（增发）
  ② 卖方 holdings 里登记 R 股买方股份
  ③ 买方的老股东被**被动稀释**（这就是“自曝的代价”，docs/19 §4.3）
```

**（3）分期 + 业绩对赌（earn-out）**
```
基准对价 = 成家价
  首付 = 基准对价 × f            （f 默认 0.4）
  尾款 = 基准对价 × (1 − f) / N   （N 期，默认 N = 2，Demo 够短）
结算时机：
  ① 签约当帧付首付 + 过户（标的先并表）
  ② 每期到期日（每 1 游戏日一期）结算一次尾款
对赌：每期挂钩标的业绩（如净资产增长 / 本季利润）
  达标记全额付；
  未达标 ⇒ **补差价** = 尾款 ×(1 − 达标比例)，从尾款里扣 / 由卖方补回
```

> ⭐ 结算时机的设计要点：**三种付款方式只在「谁先出钱、钱什么时候到、谁承担风险」上不同**，过户时点是单一的（都在签约/接受那一帧），这样引擎只需要一个 `_settleAcquisition(deal)` 出口，不必为三种方式各写一条链路。

### 4.5 举牌 / 要约：触发与后果（`docs/19 §4.11-B` 的落地）

| 门槛 | 触发 | 后果 |
|---|---|---|
| **3%** | 可提交议题 | 提案入口亮起 |
| **5%** | **举牌** | **必须公告** → `shell.cover`（隐蔽度）↓ / 关注度↑；此后**每再增减 5% 再公告** |
| **10%** | 可发起决议 | `docs/19 §8` 拍板 10% 发起 |
| **20%** | 重大影响 | 公司卡从「只读」→「可看细节」（仍进不了经营 UI） |
| **30%** | **触发要约收购义务** | **再买就得公开叫价**：对全体股东发**全面 / 部分要约**，不得私下加仓 |
| **50%** | 普通决议过半 | **控股**，普通决议你说了算 |
| **66.7%** | 特别决议 | 修改章程 / 增减资 / 合并分立 / **卖公司** |

**要约的后果链**：
```
发出要约 → 全体股东在答复期（24 游戏小时，与 proposals 同长，docs/19 §4.13-C）内决定卖不卖
  ├ 接受率达标 → 过户
  └ 接受后持股 ≥ 90% → 可强制收购剩余 → 摘牌退市（完全私有化，docs/19 §4.11-E）
反收购（NPC 防御，docs/19 §4.4）：毒丸 / 白衣骑士 / 焦土
  —— 由 NPC 人格权重驱动（w.revenge / w.patience，14-npc.js:8-11 那套权重）
```

### 4.6 市值与 IPO 的最小可玩版本

**最小闭环（建议先只做这一条，避免死代码）：**

```
每家一块「行情」：
  totalShares  默认 1,000,000（Demo 单位，不必对应现实股数）
  price        未上市 = 无（不可交易）；IPO 时初始化：
                 price0 = 评估区间中值 / totalShares
  marketCap    = price × totalShares                     ← 市值
  我的那部分   = 持股% × marketCap                       ← 计入身价
```

- **IPO**：把自己的公司（或一家 NPC）挂牌。
  - 拿到融资（现金进**公司账**，不是个人账 —— 守 `docs/19 §4.12`）；
  - 代价：**被稀释 + 变成别人的收购目标**（自曝，`docs/19 §4.3`）。
- **二级买卖**：只做**买 / 卖各一张单**，不做撮合深度（430px 放不下多列，`docs/20 §4` 已判「交易所大厅必须改版」）。
- **涨跌停保护**：复用 `s.rules.limitDown`（`03-core.js` 规则开关）；**情报放消息 / 贸易砸盘**复用现成的 `rumor` + 市场冲击模型（`docs/19 §4.6` 已列「股价操纵」的现有资产）。
- **增发 / 回购**：增发 → `totalShares↑`、老股东 %↓（稀释对手）；回购 → 用公司现金买回、`totalShares↓`（护盘）。
- **记账切换（关键）**：未上市时公司在身价里按 `navSnapshot × control` 计；**上市后**改按 `持股% × 市值` 计。**同一家公司在同一时刻只能用一种口径**（否则又撞 `docs/19 §4.10`）。

## ⑤ 落地风险（依赖哪些前置 · 会影响哪些守卫与测试 · 明确不该做什么）

### 5.1 前置依赖（不补就做不了的）
