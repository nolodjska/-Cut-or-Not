## 1. 现实依据（查到的模型 + 出处）

| 模型 | 一句话 | 用在本作哪里 |
|---|---|---|
| **Kyle's λ**（Kyle 1985《Continuous Auctions and Insider Trading》） | 价格变化 = λ × 净订单流；λ 越大＝流动性越差，同样一单砸得更狠 | §3 价格冲击 |
| **做市商保留价**（Avellaneda–Stoikov 系思路） | 做市商围绕**保留价**报买卖双边，保留价随**库存**反向调整（货多就压低） | §3 做市商行为 |
| **维持保证金 / 追保 / 强平** | 保证金跌破维持线 → 发追保通知 → 逾期未补 → 强制平仓 | **§4（就是「负债≠破产」的落点）** |
| **LBO 杠杆收购** | 自有资金只占小头，大头靠银行贷款（用**标的自身的资产抵押**）+ 发债，**用标的自身未来现金流还债**；目标 IRR 20%+ | §6 收购 |
| **沉没 / 软上限 / 对数曲线**（sim economy design 通行结论） | 收益曲线应当**对数**（早期陡、后期缓）；**没有沉没必然通胀**；软上限（不禁止、只减速）驱动多元化 | §9 |
| **短期随机、长期确定**（RNG 原则） | ±20% 方差是刺激；10 次还没到均值就是"系统坏了"。要保底/怜悯机制 | §9 |

## 2. 价值层：内在价值 → 品质 → 市场价

### 2.1 三层定价

```
内在价值 = 生产成本 × (1 + 行业加成)
市场价   = 内在价值 × 品质乘数 × 供需系数 × (1 + 操纵项)
```

- **行业加成**【提议】：制造业各行业的差异放在这里，从现实取数。
  化妆品/药品 加成高（品牌与专利溢价），电子产品 加成低（同质化、走量），箱包/奢侈品 加成最高但不稳定。
- **操纵项**（你说的"价值是人赋予的"）：由 §3 的冲击 + 情报放消息产生，可正可负。

### 2.2 品质 6 档的价格区间【提议】

**关键设计：相邻档的价格带必须重叠。** 这一条同时实现你那两句看似矛盾的要求——
「传说跌到最低档也很难比红色低」（→ 高的档**地板**更高）与「这不是绝对」（→ 带子重叠，**天花板**可以越过下一档的地板）。

相邻档乘数取 **φ ≈ 1.618**（黄金比），好记、好外推：

| 档 | 颜色 | 乘数基准 | 价格带（相对"普通基准价"） |
|---|---|---|---|
| 普通 | 灰 | 1.00 | 0.80 – 1.25 |
| 良品 | 绿 | 1.62 | 1.20 – 2.05 |
| 卓越 | 蓝 | 2.62 | 1.95 – 3.35 |
| 稀有 | 紫 | 4.24 | 3.20 – 5.40 |
| 珍稀 | 红 | 6.85 | 5.20 – 8.75 |
| 传说 | 金 | 11.09 | 8.40 – ∞ |

**验算你那句话**：传说的地板 **8.40** ＞ 珍稀的地板 **5.20** ✅（很难更低）；
而 珍稀的天花板 **8.75** ＞ 传说的地板 **8.40** ✅（**可以**越界，但窗口只有 4%，自然形成"罕见"）。

### 2.3 与代码的接线

- `CROPS` 里已有 `tier:'入门'/'主力'/'高端'` —— 那是**定位档**，不是品质档。**建议把该字段改名 `role`**，品质另开 `grade`，避免键名相撞。
- 品质不是商品的固有属性，而是**一批货的属性**：同一作物因**种子/工艺/地块品质**产出不同 grade。这样才成立"能炒"。
- ⚠️ 上品质乘数之前，**必须先补产品的价格锚**。`engine.js:686` 留了前科：
  > 实测能把辣酱价格推到 **36 万**（1e40 级净资产）。作物的锚本来就有这道夹子，产品漏了。

  乘以 11 倍品级乘数会把该失稳同步放大 11 倍。

## 3. 价格引擎：做市商 + 冲击 + 涨跌停

### 3.1 做市商保留价（新）

```
保留价 r = 基本面 × (1 − k · clamp(库存偏离, −1, +1))
库存偏离 = (做市商库存 − 目标库存) / 目标库存
```

- `mmInv`【已实现】已在引擎里，作为做市商库存。
- 含义：做市商手里的货越多，越不愿意再收，报价越低。**这是「你卖得越多价格跌得越狠」的机制诚实来源**（`08` §2.4 说这句是整个引导的成败点），也给"库存"这个状态量真正的意义。
- 【提议】k = 0.25（保留价对库存偏离的敏感度）。

### 3.2 价格冲击 λ（保留现有实现）

- `cpPerTradeVolume: 0.02` + `cpLevels: [40,110,210,350,530,760,1050,1400,1820]`【已实现】
- 这已经是**分段线性的 λ**（成交笔数越多，每笔冲击越大＝凸性）。**不要重写**，只要把 §2.2 的品级乘数接进"基本面"层即可。

### 3.3 品质与流动性【提议】

高品级流动性更薄 → λ 更大：`λ(grade) = λ₀ × gradeStep^gradeIndex`，取 `gradeStep ≈ 1.35`。
效果：**传说能炒，但炒起来的成本高、出货也难**——正好是"稀有"该有的手感，还天然防止"人人囤传说"。

### 3.4 涨跌停

【已实现】作为世界规则开关（`08` §2.3、`06`）。品质带子与涨跌停叠加时，**涨跌停优先**（硬约束不被突破）。

## 4. 杠杆层：抵押 → 授信 → 追保 → 强平 ★

**这一节是「负债 ≠ 破产」的机制落点。**

### 4.1 抵押率表【提议】

授信额度 = Σ(抵押品估值 × 抵押率) × 公司信用系数 × 授信倍数

| 资产 | 抵押率 | 理由 |
|---|---|---|
| 现金 | 100% | — |
| 普通 / 良品 库存 | 70% | 好变现 |
| 卓越 / 稀有 库存 | 50% | 流动性一般 |
| 珍稀 / 传说 库存 | **25%** | 估值波动大、出事时根本卖不掉 |
| 地块 | 60% | 有二级市场（§3 拍卖） |
| 自动化设施 | 40% | 不可移动，清算折价重 |
| 应收账款 | 50% | 有违约风险 |

- 公司信用系数【提议】：种植/制造 1.0、贸易 1.1、情报 0.9、皮包 **0.4**（“看不见的手”银行不敢多借）、金融 **2.5**（`02` §2.7 已有）
- 利息【提议】：基准 2.5%/天（`02` §2.7 已给），× 公司折价（金融 5 折）

### 4.2 维持保证金率与追保【提议】

```
维持线：净资产 / 总负债 ≥ 0.30
  ├─ 跌破 → 发【追保通知】（UI 红字 + 顶栏告警）
  ├─ 追保窗口 = 6 游戏小时（沿用现成的 graceHours: 6，不再动这个调过的数）
  └─ 窗口内补足（还钱 / 卖货 / 质押更多资产）→ 解除
              逾期未补 → 进入 §5 破产清算
```

### 4.3 结论：破产的精确判据

> **负债本身永远不是破产理由。**
> 破产 = **净资产 < 0（资不抵债）** 且 **追保窗口内无法补足**。

**由此必须废除的现状**：

| 位置 | 现状 | 处置 |
|---|---|---|
| `engine.js:59` | `arrearsLimit: 400`「累计欠款超过这个数就进入破产倒计时」 | **废除**（或降级为"追保触发线"的一个提示阈值） |
| `engine.js:836` | `breached = p.cash < 0 \|\| p.arrears > 400` | 改为 `breached = 净资产/总负债 < 0.30` |
| `engine.js:60` | `graceHours: 6` | **保留**（正好就是追保窗口） |

## 5. 破产与清算

### 5.1 单公司破产

```
净资产 < 0  且  追保窗口逾期未补  →  该公司破产
```

### 5.2 清算瀑布（现实顺序）【提议】

```
1. 强制变卖资产          （liquidationHaircut: 0.30 已实现，保留）
2. 税款 / 地租 / 手续费   （优先权最高）
3. 有担保债权人          （银行，按抵押率受偿）
4. 普通债权人            （债务包持有者）
5. 股东                  （通常归零）
```

### 5.3 与「债务包」拍品的接口【已实现，接上即可】

`engine.js:207`：`{ id:'debtpack', name:'债务包', desc:'买下它，债权人变成你：对手欠你的钱由你还。' }`
—— 清算瀑布第 4 层的受偿权，就是它。**这条拍品是巨鳄玩法的原生接口，不用新做。**

### 5.4 巨鳄出局

```
出局  ⟺  holdings 里所有公司都破产
```

## 6. 收购与合并（LBO）

### 6.1 收购价

```
收购价 = 标的 NAV × (1 + 控制权溢价)
控制权溢价【提议】25%（30%+ 控股 / 50% 绝对控股 两档可选）
```

### 6.2 三段资金结构【提议，依 LBO 现实结构】

```
自有现金  ≥ 30%
银行贷款  ≤ 70%   ← 用【标的自身的资产】抵押，抵押率按 §4.1
（可选）发债      ← 赛季版再开
```

### 6.3 债务由标的自身现金流偿还

这是 LBO 的核心，也是**巨鳄玩法真正的风险来源**：

> 买得太狠 → 合并报表净资产转负 → 触发追保 → 逾期 → 你的公司被清算 → 全部破产 = 出局。

**这条闭环就是「回环」缺的那条边**（见 §7）。

### 6.4 合并

- 产能 / 品牌 / 渠道 叠加；**债务一并并入**
- 反垄断拆包【已实现设计】：`03` §2.5.1 / §697 —— 任一玩家买下后单作物流通量 ≥45% 强制拆包（垄断门槛 60%，留 15pt 缓冲）。**直接复用，不要重定。**

### 6.5 变卖

`liquidationHaircut: 0.30`【已实现】直接复用。

## 7. 持仓层（数据结构）

### 7.1 现状

```js
// engine.js:414
id, name, corp: corp.id, corpName: corp.name, isHuman: !!isHuman
```
玩家只有**一个** `corp` 字符串。全项目满屏 `CORPS.find(c => c.id === p.corp)`。

### 7.2 提议结构

```js
p.holdings = [
  { corpId:'grow',  stake:1.00, control:1.00, debt:0, acquiredAt:0 },   // 开局自带
  { corpId:'trade', stake:0.40, control:0.40, debt:5200, acquiredAt:2880 }, // 收购来的
]
```
- `stake` = 持股比例（分红权）；`control` = 控制权（决策权，可 > stake，靠双层股权/表决权委托）
- 合并报表：`NAV(巨鳄) = Σ 控股公司 NAV × control + 非控股 stake × NAV`
- **出局 = 所有 `holdings` 里的公司都破产**（§5.4）

### 7.3 开局（QA1 已定）

**只选一家。** 各家**启动资金不同**——这一点其实【已实现】：`CORPS[].start.cashMod` 让六家初始现金不同（`08` §153-156：种植 7,600 / 贸易 8,440 / 情报 8,800 / 皮包 8,800）。
你担心的"成本太高、制造业要倒闭"正是**开局只选一家**要解决的：选制造业就把钱全押在一条产线上，玩家要自己判断这个赌注划不划算。

## 9. 软上限与沉没（防通胀清单）

研究结论：**没有沉没的模拟经济必然通胀**；软上限（不禁止、只减速）驱动多元化。

### 9.1 现有沉没【已实现】

| 沉没 | 数值 | 出处 |
|---|---|---|
| 地租 | 40 G/天/块（第 1 天免收） | `06` Q-TIME-03 / §4.3 |
| 手续费 | 1.4%–2%（公司有折） | `engine.js:957/1063` |
| 贷款利息 | 2.5%/天 | `02` §2.7 |
| 拍卖抽成 | 3 天约抽走 7.8% 货币 | `08` §617 |
| 加工耗时 | 2/3/8 游戏小时 | `PRODUCTS` |

### 9.2 缺的沉没【提议，取现成的】

| 建议新增 | 理由 |
|---|---|
| **仓储超限费** | 现在仓储只是硬上限，没有"占着仓储要花钱"的软压力 |
| **自动化设施维护费** | 研究原文：设备维护是最典型的沉没；也给"买断自动化"加上持续成本 |
| **品质维护成本** | 高品级库存要占仓储/要保养 → 天然压制"人人囤传说" |

### 9.3 软上限（已有，别加）【已实现】

`float0`（流通量）+ `absorbDay`（NPC 日吸收）+ `mono`（垄断门槛）**本身就是软上限**。
另按研究建议可叠加：**重复卖同一个商品 → 价格衰减**（已有）、**过度种同一作物 → 品质下滑**（正好接上 §2 的品质 6 档）。

## 10. 平衡表口径

### 10.1 统一用 PPM

研究给的核心平衡列：**PPM = 利润 / 分钟**。建议 `09` 数值表统一加这一列——现有 `06` §4 的「种地不能太赚」算术验证可以改写成 PPM 比较。

### 10.2 四个要监控的信号（研究原文）

1. **被动收益堆积了多少？** 太多 → 沉没不够
2. **玩家是不是只做一件事？** 只有一个赚钱点 → 其他点要调
3. **哪一类玩家/NPC 被跳过了？** 不值当 → 奖励要重审
4. **第一个流失点在哪？** 几乎总是节奏问题

## 13. 市场参与者谱系（全部按现实标准）

> **原则（用户 2026-10-08 定）：不发明机制，只把现实里的摩擦搬进来。**
> 现实已经把定价、出清、风险转移、资本配置、规则执行解决过一次；
> 游戏性是这些机制**自带的副产品**，不是设计出来的。
> 本文所有角色都能在现实里指名道姓找到对应物。

### 13.1 六层职能 → 现实角色 → 现状

| 层 | 现实角色 | 你现有 | 缺口 |
|---|---|---|---|
| **需求** | 分收入层的消费者 / 工业用户（派生需求）/ 政府采购 / 出口需求 / 投机需求 | `absorbDay` 常数 + `floorBuyerMult` / `importValveMult` 两道夹子 | **整层缺"人"** |
| **供给** | 生产者 / 进口商 / 囤积者 | ✅ 种植·制造 + 进口阀门 | 囤积者＝玩家自己，够用 |
| **中介** | 做市商 / 经纪 / 交易所 / 清算所 / 仓储 / 评级 / 审计 / 鉴定 / 保险 / 投行 / 秃鹫基金 / 对冲基金 | 只有 `mmInv` 一个**数字**，没有实体 | **12 个角色，缺 12 个** |
| **资本** | 商业银行 / 中央银行 / 存款保险 / 股东（委托代理） | NPC 银行（存/贷） | 央行·存保·股东缺 |
| **规则** | 财政 / 监管 / 立法 / 法院 / 执法 | 开局摇一次的 6 个布尔（`engine.js:300`） | **整层无实体** |

**核心诊断**：玩家现在是在跟**系统的边界**博弈，不是在跟**人**博弈。
需求是常数、做市商是数字、政府是布尔、事件无制造者。
而 `08` §2.4 说引导的成败点是「玩家意识到**市场不是背景，是另一个玩家**」——**现在市场里一个人都没有。**

### 13.2 现实白送的 8 条游戏性（最高杠杆：机制 → 自动产生的玩法）

| # | 现实机制 | 自动产生的玩法（不需要设计，它本来就会发生） | 接你哪个字段 |
|---|---|---|---|
| 1 | **逆向选择**（adverse selection）：做市商分不清你是不是内部人 | 你有情报优势 → **做市商对你扩价差 / 撤报价** → 情报优势自带成本，**自动平衡情报公司**（准确率 100% 不再是纯收益） | `intelInsiderAcc` + 做市商 |
| 2 | **库存回补**：做市商被砸出负库存后**必须买回来** | 砸盘之后价格**自动反弹**，且回补节奏可预测 → **可以埋伏自己的砸盘** | `mmInv` / `mmInvMax` |
| 3 | **仓单质押 + 重复质押**（现实：**青岛港 2014** —— 德诚矿业**让四家不同仓储公司分别出仓单**，钻**银行间信息不对称**的漏洞去不同银行重复质押，贷款敞口**超 10 亿元**；败露方式是**仓单与实际库存对不上**） | 皮包公司拿隐蔽库存重复融资。**完整链条＝多家仓储商 + 银行间不共享信息 + 撞库查仓** → 三个环节都该有实体 | 深仓天赋 `hiddenStorage: 100`、`shell.owned`、`storageCap` |
| 4 | **浮存金**（float，**已验证**）：保费**入账即负债**（会计上列「应付账款」），出事才赔；中间的钱可以投资，所以伯克希尔拿到的是**「负成本」资金** | **收购保险商 = 用负债换现金**。关键：它**自动接入刚建好的 `maintRatio`** —— 收保费立刻抬高负债 → 逼近追保线；投资一亏 → 净资产跌而负债不变 → **追保 → 被迫卖 → 保证金螺旋**。AIG 就是这么死的。**零新代码** | `rotH` 腐坏 + 天灾事件 + **`maintRatio`** |
| 5 | **保证金螺旋**（margin spiral）：价格跌 → 追保 → 被迫卖 → 价格更跌 | **你砸盘，对手被自己的追保逼死，你去收尸** —— 全自动，不需要写"打压"指令 | 刚建的 `maintRatio` + 拍卖「破产资产包」 |
| 6 | **挤兑**（bank run）：借短贷长，信心一破就挤兑 | **打一家公司最狠的方式是打它的银行**（放消息 → 储户排队） | `depositRateDay` / NPC 银行 |
| 7 | **监管俘获**（regulatory capture）：旋转门、游说、政治献金 | 请退休官员进董事会 → 你改的不是市场，**是规则本身** | 需新实体（监管） |
| 8 | **大到不能倒**（too big to fail）：道德风险 | **"最强"的另一种定义：不是资产最高，而是"我不能死"** | 需新实体（央行救助） |

> **事实核验（2026-10-08，用公开报道核对）**
> - **#3 青岛港 2014 ✅**：德诚矿业让四家仓储公司分别出具仓单 → 利用银行信息不对称去不同银行重复质押 → 敞口超 10 亿元；发现方式是仓单与实际库存有缺口。
> - **#4 浮存金 ✅**：保费并非保险公司资产，会计上列「应付账款」、**属于公司债务**；短期险保费（Float）的投资收益几乎就是利润；伯克希尔因此拿到**「负成本」资金**。
> - **#6 挤兑 / 期限错配 ✅**（2007 资产票据市场流动性危机 → 2008 初贝尔斯登被挤兑 → 雷曼后货币市场基金挤兑）；
>   但 **「SIV」这个具体名称未被搜到的来源直接印证**，只印证了它所属的「资产票据市场」。此条按**未完全核验**对待。

### 15.1 框架纠正（重要）

我在 §13.1 用的六层分类（需求/供给/中介/资本/规则/信息）是**教科书式干净**的，
但现实中**同一主体经常跨层**：保险公司既是资本侧（配置资产），又是信息侧（精算定价），
还是需求侧（买债券）。**做角色表时不能假设一个角色只属于一层** —— 这直接影响"玩家收购一家公司后获得什么能力"的设计。

|---|---|---|

### 15.3 它对"我的理解有错"的纠正（两条，都很关键）

**纠正 ①：仓单案不是"银行被骗"，而是"银行主动简化核查"。**
因为核查成本高、单笔贷款收益有限，银行"筛选出地方政府可能背书的红顶企业，**而忽略了对质押品本身的充分调查**"。
⇒ 这**不是被动受害，是风险定价能力不足下的主动取舍**。
**设计含义**：皮包公司重复质押的破解，不该是"银行抽检随机发现"，而应该做成
**一笔收益 vs 核查成本的经济账** —— 小额贷款**理性地不核查**，所以**拆小额度**才是有效的骗贷策略。这一条直接给出了一种玩法。

**纠正 ②：六层分类不能假设角色只属一层**（见 §15.1）。

### 15.4 六条机制 → 可直接落地的玩法

| 机制 | 落地成什么 | 接现有字段 |
|---|---|---|
| 做市商库存 | dealer 有**库存上限**与**资本**；击穿后**顺势砸盘**；资本足 → V 型反转可埋伏；资本耗光 → 直接停止做市（市场冻结） | `mmInv` / `mmInvMax`（现在只是硬顶，要变成"有资本的实体"） |
| 保证金螺旋 | 追保→被迫平仓→更跌，**小时级、非线性**；危机中**暂停交易 + 取消价格**是真实处置手段（LME） | 刚建的 `maintRatio` + 「破产资产包」拍品 |
| 仓单重复质押 | 仓单可质押；**拆小额度规避核查**；揭发点在**提货**；仓储方共谋则完全隐蔽 | 深仓天赋 `hiddenStorage` + `shell` |

| 挤兑 | **信心值**跌破阈值 → 取款非线性上升 → 24 小时内不可逆 | NPC 银行 `depositRateDay` |

## 16. 内化与暴露（用户 2026-10-08 定：**可以内化，绝不能暴露**）

> 原话：「玩家并不知道这些概念，所以我们可以内化，但是不能暴露，因为暴露意味着用户
> 瞬间面临一堆完全不知道什么意思的信息。**我们需要他们自己去学。**」

### 16.1 两条轴必须分开（关键）

项目里 `tools/lint-copy.cjs` 一直在管**红线词**，但那是**合规轴**（微信小程序审核，`docs/07 §2.8.3`）——
它**不管认知负担**。所以本次新增了**第二条轴**：

| 轴 | 例子 | 目的 | 状态 |
|---|---|---|---|
| **合规**（`BANNED`） | 投资 / 理财 / 做空 / 杠杆 / 保证金 / 套利 / 爆仓 | 过审 | 已有 |
| **认知**（`TERMS`） | 维持线 / 追保 / 做市商 / 浮存金 / 挤兑 / 监管俘获 | 玩家不懵 | **本次新增** |

两条轴**规则完全相同**：`lint-copy.cjs` 先剥掉注释，所以
**注释里可以自由讨论术语，玩家看得到的字符串里一个都不许有**。

### 16.2 术语 → 人话 对照表（改文案前必查）

| 内部（引擎 / 文档可用） | 玩家可见（UI / 日志必须用） |
|---|---|
| 维持保证金 / 维持线 / `maintRatio` | 不出现任何百分比口径 → **「你欠的账快赶上手里的家底了」** |
| 追保通知 / margin call | **「有人上门催债」** |
| 资不抵债 | **「手里的家底抵不过欠账」** |
| 保证金（卖空押金） | **「押金」** ← 项目原有约定，`engine.js` 注释写着「原名做空，UI 禁用该词」 |
| 做空 | **「借货看跌」** ← 同上，已有 |
| 破产清算 / 出局 | **「出局」「拿地、货、公司抵债」** |
| 清算瀑布 / 优先受偿 | 不出现 → 只体现为**「先还谁、后还谁」的结果顺序** |
| 做市商 | **「收货的」「收粮的」** ← 一个常年收货的商人 |
| 库存偏离 / 保留价 | 不出现 → 体现为 **「你卖得多，他收得便宜」** |
| 逆向选择 | 不出现 → 体现为 **「你一有大消息，他就不肯给好价」** |
| 浮存金 / 承保 / 综合成本率 | 不出现 → 体现为 **「先收保费，赔款慢慢来」** |
| 监管俘获 / 旋转门 | **「有人打过招呼」** |
| 挤兑 / 信心值 | **「挤着取钱」** ← 变量名绝不出现 |
| 保证金螺旋 | 不出现 → 体现为 **「他被催债，只好贱卖家当，价格更低了」** |
| 流动性 / 期限错配 | 不出现 → 体现为 **「想卖卖不掉」「借短的钱撑长的账」** |
| 派生需求 / 价格弹性 | 不出现 → 体现为 **「他是拿去用的，不是拿去卖的，所以贵也得买」** |

### 16.3 三层暴露模型（让玩家自己去学）

| 层 | 内容 | 何时可见 |
|---|---|---|
| **第 0 层 · 现象** | 价格、成交量、催债、被卖、没人收货 | **永远可见** |
| **第 1 层 · 命名** | 术语本身（"做市商""追保"） | 玩家**自己撞到过之后**，在图鉴 / 帮助里**解锁词条** |
| **第 2 层 · 公式** | λ、`maintRatio`、库存偏离系数 | **永不暴露**（巨鳄只看账本，不看公式） |

**推论**：把"学会一个机制"做成**可解锁的图鉴词条** →
**学习本身变成玩法**，而不是教程负担。这条正好复用已有的**天赋「点亮」**手感。

### 16.4 四条硬规矩（否则玩家永远学不会）

1. **每个隐藏机制必须至少有一个"玩家可见的症状"。**
   术语可以藏，**现象不能藏**：做市商不能叫"做市商"，但他**报价变宽**必须看得见。
   没有症状的隐藏机制 = 玩家眼里的「**游戏在作弊**」。
2. **可归因**：玩家死了要能查到 **3 步前的原因**（日志 + 动态）。
3. **不做教程弹窗解释概念。** 让他先被催一次债，第二次遇到时他自己就懂了。
4. **同一机制，两套名字**：引擎与文档用术语（可搜索、可讨论），UI 用人话（可感知）。

### 16.5 执法：闸门已建成并反向验证

`tools/lint-copy.cjs` 已扩成**双闸**（红线词 + 术语暴露），并带**闸门自检探针**
（每次运行拿「追保/维持线/做市商」撞一次自己，防止闸门因写错而**静默失效**）。

**反向验证已通过**：往 `ui.js` 塞一个「做市商」→

```
❌ game/ui.js … **术语暴露** 1 处（玩家会看不懂，换成现象说法，见 docs/13 §16.2）：
    L462 「做市商」 …可以收割了（做市商）…
结论：❌ 有 1 处需要处理            probe_lint=1
```

精确定位行号 + 指向本对照表 + 退出码 1。撤掉探针后复归全绿。

⚠️ **踩坑记录（重要）**：第一次反向验证我用 `Add-Content` 往 `index.html` 塞探针，**闸门没红**。
原因是 PowerShell 的 `Add-Content` 默认按 **GBK** 写，而 Node 按 UTF-8 读 → 探针变乱码 → 匹配不到。
**这实证了项目「不许用终端写文件」那条规矩的必要性**：它会**静默损坏编码**，把验证变成假的。

**同一天第二次踩同一个坑（这次是"读"的那一侧）**：我写了个校验脚本，用 `Get-Content -Raw` 检查
`TERMS` 列表是否覆盖 §17 宣告的词，结果**把所有词都报成"不在闸门内"**——包括我确定刚写进去的 `做市商`。
已实测证明原因：

```
默认编码读到 '做市商' 吗： False
UTF8 编码读到 '做市商' 吗： True
默认编码下的开头： /* 鏂囨绾㈢嚎妫€鏌ワ紙docs/07 搂2.8.3 寰俊灏忕▼搴忓鏍哥…
```

`鏂囨绾㈢嚎` 就是 **UTF-8 被当 GBK 读**的典型乱码。**这台机器上 PowerShell 默认编码是 GBK，而项目文件全是 UTF-8。**

**结论（升级为纪律）**：在这个项目里——
- **写**：一律 `write(mode=file)`；绝不用 `Add-Content` / `>` / `Set-Content`
- **读**：一律用 `read` 工具，或 `Get-Content -Encoding UTF8`
- **中文匹配 / 校验**：绝不用 PowerShell 默认编码跑

⚠️ 两次都是**静默**失败：不报错，只是**结果变成假的**——这比直接报错危险得多。
**凡"检查通过"，先确认检查本身没被编码骗过。**

## 17. 症状清单（Tier 1 三个角色）

> 这是 §16「内化与暴露」的落地件。**先定症状，再写代码**——
> 因为症状决定了数据要怎么存（存不出症状的字段就是废字段）。

### 17.0 什么叫「症状」：六条判据

一个隐藏机制要能被玩家**自己学出来**，必须有症状。合格症状要同时满足：

| # | 判据 | 反例（不合格） |
|---|---|---|
| 1 | **当场可见**：你点下去的那一刻数字就变了 | 「收盘后统计报告」——玩家当时没感觉 |
| 2 | **有方向感**：能看出「因为我做了 X，所以 Y 变了」 | 价格随机抖动 —— 学到的是玄学 |
| 3 | **有原因**：角色的行为必须能从他**可见的状态**推出 | 他无故改价 → 玩家只能猜 |
| 4 | **只教 1~2 条规则**：多了就是术语淹人 | 一个界面同时教 6 件事 |
| 5 | **互相咬合**：角色 A 的症状会改变角色 B 的行为 | 各自独立的孤立系统 |
| 6 | **可归因**：能在动态里查到原因（§16.4 硬规矩②） | 「你破产了」但不说什么导致的 |

**第 3 条是精髓**：**不能有玩家看不到的原因**。否则玩家学到的是"这游戏随机"，不是"这游戏有规则"。

### 17.1 ① 收货商 —— 做市商的症状化

> **内部名**：做市商 / dealer　**现有字段**：`mmInv` / `mmInvMax` / `absorbDay`
> **现实原型**：产地收购站、粮商（嘉吉/托克式）
> **界面身份**：一个**常年在收货的人**（有名字、emoji/SVG 头像）——**绝不能叫"做市商"**

现有 NPC 人格已有 6 位（老陈/阿May/眼镜/坤叔/祥嫂/钱串儿），这位是第 7 位，或直接复用其中一位。

| 玩家看见什么 | 他自己会推出的规则 |
|---|---|
| 他的**收货价**总比"你买回来"的价低一点 | 中间有个差价 |
| **你一次卖很多，他的价当场往下走**（实时可见） | ⭐**「我卖得越多，价格跌得越狠」** ← `08 §2.4` 的成败点 |
| 卖完过一会儿，那价**自己慢慢爬回来** | 有人会在低价时买回去 → **砸盘之后可以埋伏** |
| 他摊上一块牌子：「**今日还收 N 单位**」 | 他的胃口是有限的 |
| 牌子变成「**收满了，明天再来**」 | 市场会**冻结**（不只看价格，还看有没有人接） |
| **你一拿到情报就去找他，他立刻把牌子上的价往下调** | 你太准了 → 他会防你 → **情报优势自带成本** |

**归因句（日志格式，复用现有写法）**：
> 「你把萝卜按 10.54 卖了 94 单位 —— 他的收货价降到 9.88（今日还收 210 单位）」

**绝不允许出现**：`做市商` `库存偏离` `保留价` `逆向选择` `流动性` `mmInv` `报价价差`

**第 1 层命名解锁**：撞到 3 次之后，图鉴里出现词条「**收货商**」。

**⚠ 已有约束**：拍卖**明确不用单一价**（防自成交拉价）→ 收货商报价走**逐笔/分档**，不要引入"统一清算价"概念。

### 17.2 ② 上门的买家 —— 需求侧的症状化

> **内部名**：需求侧 / consumer + industrial　**现有字段**：`absorbDay` / `floorBuyerMult` / `importValveMult` / `brand`
> **现实原型**：分收入层的消费者 + 派生需求的工业用户
> **界面身份**：**几个会主动来找你买货的人**（而不是你去市场卖）——这是关键差异：
>   让玩家第一次感觉到「**市场不是背景，是有人在外面等我**」

三类人（对应现实的三层需求）：

| 谁 | 现实对应 | 他的脾气 |
|---|---|---|
| **街坊** | 低收入消费者 | 买得多、出价低、只认便宜货 |
| **作坊主** | 工业用户（派生需求） | **贵也得买**，因为他是拿去加工的 |
| **豪客** | 高净值 / 投机需求 | 出价高、量小、**只买一次** |

| 玩家看见什么 | 他自己会推出的规则 |
|---|---|
| 三类人**要的货不一样** | 不同的货有不同的底盘 |
| **同一个人，你卖他越多，他出价越低** | 需求会吃腻（饱和） |
| **作坊主：你涨价他也买** | 他是**拿去用的**，不是拿去卖的 |
| 偶尔来个**生面孔，出价很高，但只买一次** | 一次性机会，抓住了就赚 |
| **见过三次之后，他出价略高一点** | ⭐回头客 —— **`brand` 终于有了可见形态**（现在它只是个看不见的乘数） |
| 总需求**每天略多一点** | 经济在长大（支撑"引领一群公司变好"那条路线） |

**归因句**：
> 「街坊今天已经买了 60 单位萝卜 —— 再卖他，他只肯出 8.2」

**绝不允许出现**：`需求曲线` `价格弹性` `派生需求` `边际消费倾向` `饱和` `需求侧`

**第 1 层命名解锁**：见过 3 类买家之后，图鉴出现「**街坊 / 作坊主 / 豪客**」。

### 17.3 ③ 验货的老手 —— 鉴定行（品质 6 档的认证方）

> **内部名**：评级 / 质检 / 公证　**现有字段**：**无**（品质 6 档待建）
> **现实原型**：质检公证 + **评级机构（含被俘获的评级机构）**
> **界面身份**：一个可以**送件去验**的人

| 玩家看见什么 | 他自己会推出的规则 |
|---|---|
| 你的货里**有几件标着好货，有几件说不清** | 货分档 |
| 送一件去验：**要收钱 + 要等** | 验货有成本 |
| 验完货上**多一个印** | — |
| **有印的货，卖价明显更高** | 品质＝钱 |
| ⭐**花钱能让他"通融一下"**（给个更漂亮的印） | **印是可以买的** |
| **偶尔有"查的人"来**，之后他一段时间不敢通融 | **买印有风险** |
| **你把这家鉴定行买下来之后**，可以给自己的货盖章 | 中间人可以据为己有 |

**归因句**：
> 「老周给那批人参盖了印，收了你 320 G —— 柜台里那批没印的还堆着」

**绝不允许出现**：`评级机构` `监管俘获` `旋转门` `公证` `质检标准` `信用评级`

**⭐ 这里是整套设计里最漂亮的一处内化**：
玩家**永远不会**看到"监管俘获"这四个字，但他会自己学会
**「钱能买印，但有风险；不买印就卖不上价」**。
—— 这正是 §16 说的「**我们需要他们自己去学**」。

**注意**：与记忆里的品质设定一致 —— **品级决定价格区间，但非绝对，价值由人赋予**。
所以印不是"改数值"，而是"**别人愿不愿意信**"——同一批货，有印和没印是两个价。

### 17.4 出场顺序（教学节奏）

| 顺序 | 角色 | 什么时候撞上 | 凭什么自然撞上 |
|---|---|---|---|
| **第 1 撞** | **收货商** | 开场 5 分钟内 | 种第一块地 → 收割 → 去卖 → **亲眼看见自己的大单把价压下去** |
| **第 2 撞** | **上门的买家** | 第一次有货但卖不动 | 货压手里 → 有人**主动上门**出价（还比市场价好） |
| **第 3 撞** | **验货的老手** | 手里出现"说不清"的货之后 | 卖不上价 → 有人提醒"你这批货，验一下能多卖" |

**第 1 撞是全局成败点**（`08 §2.4`）。前 5 分钟必须让它发生，否则玩家永远把市场当背景。

### 17.5 通用法则（可复用到后续所有角色）

1. **一个角色 = 一个人 + 一块会变的牌子**。牌子是他**可见的状态**（今天还收多少 / 已经买了多少 / 敢不敢通融）。
2. 症状**必须当场可见**，不能是事后统计。
3. 症状**必须有方向感**（X → Y）。
4. 每个角色**只教 1~2 条规则**。
5. 角色之间症状要**互相咬合**：收货商收满了 → 买家的货更值钱 → 玩家自己推出"市场是一个整体"。
6. ⭐**角色的行为必须能从他的可见状态推出原因。绝不能有玩家看不到的原因。**
   这条决定"玩家学到的是规则，还是玄学"。做法：**把 AI 的随机性挂到牌子上**，
   例如"他今天心情不好"要改写成"**他今天收满了**"——同一件事，后者可学，前者不可学。
