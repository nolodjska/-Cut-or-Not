## 一、它抓出的核心 bug（3 条硬伤）

### 🔴 BUG 1：收货商的牌子**永远是「收满了」**（第 1 天 17:31 就是）

**证据（试玩员原话）**：
> 「萝卜那张牌，我从头到尾没见过数字……一直到第 3 天 23:05 还是这句。
>   我一次都没见过萝卜的『今日还收多少』。」

**根因（读代码确认，不是猜）**：

```js
// 改前（engine.js L1095）
if (c.absorbDay && !this.isProduct(cid)) c.absorbedToday = (c.absorbedToday || 0) + qty;
```

`_trade` 对**所有人**调用 → **NPC 也在累加**。萝卜 `absorbDay = 800`，
几百个 NPC 几分钟就吃光 → 玩家的牌子永远是满的，而且**每一单都吃 ×2.5**。

**⚠ 更要命的是这只违反项目第一纪律 `§17.0 判据 3`**：
NPC 在卖是**玩家看不见的原因**。牌子上每个数字都必须能由玩家自己的行为解释。

**修正**：额度**按玩家计**。
- 新增 `p.dealerSold` / `p.dealerSoldDay`
- 新增 `Game.prototype.dealerQuota(cid)`（= `absorbDay × BAL.dealerQuotaMult`，萝卜 → 80）
- 新增 `Game.prototype.dealerSoldToday(p, cid)`
- `_impact` / 归因句 / 牌子全部改走这三个

### 🔴 BUG 10：**新手主线在亏钱** —— 漏斗杀手

**证据（试玩员原话）**：
> 「我玩了整整一局，什么都没做错（就是种→收→卖这一条主线），
>   结果净资产反而变少了（10,000 → 9,577）。」

**因果**：BUG 1 让每一单都吃 ×2.5 → 卖 30 单位只值 8.89/单位 → 种→收→卖净亏。

**修正 + 已量**：新建 `tools/newbie.test.cjs`（单轮 + 三轮两种口径）。

| 口径 | 结果 |
|---|---|
| 单轮（前 5 分钟） | **5/5 跑赢，平均 +86** |
| 三轮（模拟 3 天局） | **5/5 跑赢，平均 +220**（行价 10.12→8.49 一路跌，仍然为正） |

### 🔴 BUG 14/2：文案**在骗人** —— 「今日收满了，明天再来」却能卖

**证据**：
> 「写着『今日收满了，明天再来』，却能卖、还真成交了……
>   这句『明天再来』到底是拒绝还是只是提示要压价？我完全分不出来。
>   单看这件事，**让我觉得规则在骗我**。」

**根因**：这是我**故意的设计**（不拒绝成交，防死局），但**文案与机制相反**。
§17.0 的纪律是「玩家推出来的规则必须与机制一致」。

**修正**：牌子改成说实话 + 主语说清 + 因果说全
- 未收满 → `🧺 老赵的收货摊：今天还能收 N 单位（只算你卖的 · 天亮回满）`
- 已收满 → `🧺 老赵的收货摊：今天收够了（还卖得动，但他会往死里压价 · 天亮回满）`

### subagent ①：`general-agent` —— 修 `tools/serve.cjs`

**它推翻了我的判断，而且证据比我的硬。** 我此前写：
> 「问题不在页面、不在面板，在我 `serve.cjs` 那条 `http://` 路径」（凭“同文件、同面板、只有 scheme 不同”的 A/B）。

它给了三条反证：
1. **字节一致**：HTTP body 与磁盘逐字节相同（SHA256 对得上）→ 排除“发错字节/截断/BOM”
2. **真浏览器 A/B**：`http://` 与 `file://` 两边都是 `appW430 dpr1`，一字不差
3. **机制上不可能**：`2×2` 报的是 `window.innerWidth`，它是**视口/窗口**属性 ——
   任何响应头都改不了；只有窗口尺寸或设备模拟能把 innerWidth 变成 2

→ **结论：`2×2` 是面板侧窗口/设备模拟的产物，不在服务端。它没找到根因，也没编造。**

**我的教训**：我那个 “A/B 隔离” 是**坏的** —— 我把 `about:blank → http → file`
三次调用的视口拿来对比，而**面板的窗口尺寸本身会在两次调用之间变**。
变量不是 scheme，是面板当时的宽度。**我没控制变量，就把结论写成了笃定句。**

（它顺手补齐了 `serve.cjs` 的真缺陷：原先**全程 chunked、无 Content-Length、无任何缓存头**；
现在有 `Content-Length`/`ETag`/`Range`(206/416)/`405`/`no-store`，HEAD 也带长度。）

### 📌 并行开发的硬约束（给后续参考）

**本项目只有 2 个大文件**（`engine.js` 2700+ 行、`ui.js` 1387 行），
而 `write` 是“读-改-写”：**两个 subagent 同时改同一个文件会互相覆盖**。所以：
- ✅ **可并行**：互不重叠的**新文件**（新测试）、**只读审计**、单文件工具（如 `serve.cjs`）
- ❌ **不可并行**：同一 `engine.js` 里的多个修复 → **必须串行**

本轮就是这么分的：subagent 做 `serve.cjs`（单文件）+ 审计（只读），
**`engine.js`/`ui.js` 的修改全由我一人串行完成**，零冲突。
