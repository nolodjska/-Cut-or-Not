# 04 肉鸽天赋与NPC人格

> 本文件基于 `00-策划案-原始冻结版.md` 做「评审 + 丰富」，不改动冻结版任何结论。
> **本文所有数字均为「提议值（待校准）」**。全局锚点：玩家初始净值 1000（现金 800 + 4 地块 × 50），Demo 局时长 72h，3 种作物，1 个 NPC。

---

## 0. 摘要

- **世界种子是可复现的确定性函数**：`GG-{7位内容}{1位校验}`（Crockford Base32），同一字符串在服务端/客户端/任何设备上必须还原出**逐位相同**的世界配置；9 个字段各自用独立 PRNG 子流，改一个字段不雪崩。
- **规则变异共 24 条**，每局抽 **0-3 条**（权重 20/45/27/8）。每条对 A/B/C/D 四路径标注量化幅度（±1 ≈ 相对胜率 ±8%），并受**预算约束**：单路径累计 |幅度| ≤ 3，全路径合计 ≤ 6。`裸卖空 + 无涨跌停 + 情绪市场` 这类碾压组合被预算硬性拦掉。
- **天赋共 27 个**（种植/市场/斗争各 9），一局最多抽取 **10 次**（Lv1 首次免费 + Lv2-Lv10 各 1 次），因此**一局最多点满 1 系 + 1 个**，跨局换系才是重玩价值来源。
- **资本点数（CP）曲线**：Lv2-Lv10 累计阈值 40/110/210/350/530/760/1050/1400/1820。三天实测——休闲玩家 **Lv4**（4 天赋）、正常玩家 **Lv5**（5 天赋）、精细玩家 **Lv7**（7 天赋）。正常玩家日均 CP ≈ 150，来源占比 种地 60% / 交易 27% / 低保 13%，收购为一次性红包。
- **3 选 1 有三重防废卡机制**：至少 1 张来自本公司类型主色谱系、至少 1 张匹配当前最高路径分、至少 2 张「当前可立即生效」；另有软保底（连 2 次无稀有 → 第 3 次强制稀有+）与每局 1 次免费重抽。
- **NPC 人格 7 种**，统一用 5 维向量（风险/攻击/信息/耐心/报复）+ 一个效用函数驱动，不写 7 套 AI。Demo 只用 1 个：**鹰派降档版（雏鹰）**，参数 0.7/0.65/0.35/0.30/0.6，初始净值 1200，破产倾向 25%，带「怜悯闸门」（玩家净值 < 400 时停止主动打压）。
- **跨局只保留广度：图鉴 / 天赋解锁（进池但抽取次数不变）/ 成就与皮肤 / 好友与恩怨账本 / 外观兑换的活跃点**。明确不保留净值、地块、库存、市场影响度。硬约束：**任何跨局因素对单局最终净资产的加成 ≤ +5%**；反例 5 条（继承净值/开局天赋/NPC 好感折扣/情报订阅/垄断壁垒）已给数值推演，作为技术分支黑名单。
- **公平性四层补偿**：L1 世界适应包（按四路径最低 f 值对称发资源）+ L2 天赋池自适应（被削路径权重反向上调，并投放替代天赋）+ L3 多人局路径配额与补偿 + L4 落后玩家翻盘券（1 张/局，净资产 < 中位数 50% 才可领）。随机决定的是**起跑姿势**，不是**终点线**。
- **三种结局的重开成本不同**：破产无遗产但进图鉴；被收购触发「复仇开局」，遗产 = 上局净值 **12%、上限 300**（= 初始资产 30%）+ **自选 1 个已点天赋** + 1 份仇敌档案，且第 1 天公开挂「复仇者」标记、NPC 攻击性对其 ×1.3。复仇开局胜率目标 **22-25%**（6 人局基准 16.7%），不是翻倍。
- **与其它分支的耦合点集中在 6 处**：种子→价格引擎注入、胜利路径打分 API、拍卖场次与狙击窗口、情报真假与识破、结算「逆风/顺风」标注、种子 PRNG 与行为日志 schema。

## 1. 评审：问题与风险

- [P0] **「随机的是机会不是结果」在原案里是空话，规则变异直接改写胜负天平。**
  → 为什么：C 路径（垄断）依赖做空/逼仓工具链；若本局未抽到「裸卖空」且「仓储减半」，C 路径的达成率相对基准可能掉 30%+，而 A/B 路径几乎不受影响。玩家开局就看到一个自己打不了的局，肉鸽的「多样性」变成「被剥夺选择权」。
  → 建议：引入**路径难度系数 f(A..D)**（由 24 条规则变异的幅度累加得出，范围 [-3,+3]），并挂四层补偿（见 §2.5）。结算称号按 f 值标注「逆风/顺风」，逆风达成的称号带金边——把不平衡转成荣誉。

- [P0] **肉鸽重开与放置积累在本作里是同一个「时间」上的两笔账，原案没有回答冲突。**
  → 为什么：放置玩法的心理契约是「我今天的投入明天还在」。3 天 Demo 里玩家刚把地块升到 2 级就重开，会直接判定「白玩了」。这不是数值问题，是玩法信任问题。
  → 建议：把重开周期和积累周期**错频**——单局 3 天（战斗层，允许清零），账户层（图鉴/天赋池/成就/恩怨账本）永不清零且每局必涨。硬指标：**每局至少产生 3 个「账户层可见增量」**（新词条、新天赋解锁、新成就），否则视为该局失败设计。

- [P0] **天赋 3 选 1 与公司类型/胜利路径的耦合会大量产出废卡。**
  → 为什么：种植公司玩家抽到「裸卖空」「狙击手」等于什么都没得到；若连续 2 次升级都这样，玩家会认为系统坏了。原案只写了「保证每局 Build 不同」，没写「保证每张卡在当前局面下有意义」。
  → 建议：三重约束抽取（§2.2.3），并给出可验证指标：**任意一次 3 选 1 中，废卡数 ≤ 1**。同时把「非本系卡」的比例控制在 ≤ 1/3。

- [P1] **CP 获取速率和作用量从未定义，「3 天能成长到什么程度」不可算。**
  → 为什么：这决定了天赋是「点缀」还是「主轴」。若 3 天只能点 1-2 个天赋，天赋树就是装饰；若一天点满，则肉鸽 Build 失去意义。
  → 建议：锚定 **3 天正常 Lv5 / 5 个天赋**（§2.2.1），即「约半系」。这是唯一能同时让「有 Build」和「每局不同」成立的区间。若实测偏离 ±1 级，优先调阈值而不是调天赋强度。

- [P1] **Demo 只有 1 个 NPC，人格系统无法被验证。**
  → 为什么：7 种人格的价值在「对比」；只有一个 NPC 时玩家看不出「这货是鹰派还是老农」，人格退化成难度旋钮。而人格若被设计得很强，3 天短局里玩家第 2 天就出局，直接被劝退。
  → 建议：Demo 不验证「人格差异」，只验证「一个有人味的对手是否比一个最优策略机器人更耐玩」。把这个 NPC 做满台词/蠢事/记仇，宁可人格参数不极端。Demo 目标：**玩家在第 1 天结束时能给这个 NPC 起外号**。

- [P1] **原案「被收购 → 复仇开局 → 带少量遗产」中「少量」不可实现，且存在养猪漏洞。**
  → 为什么：遗产给 5% 等于没给（玩家没有翻盘体感）；给 40% 则连续被收购＝滚雪球式变强，出现「故意被收购攒遗产」的退化策略。
  → 建议：遗产必须**封顶且不累积**：12% 净值、上限 300、+1 个天赋、+1 份仇敌档案（§2.6），并且**只有在「被收购」结局下发放**，破产不发放。加上复仇标记的公开代价。

- [P1] **种子只做了「随机」，没做「可复现」。缺了可复现，社交卖点的一半直接消失。**
  → 为什么：「同学的同一局世界」「每日挑战」「种子分享」「赛季排行榜只在同种子组内比较」全都需要种子→配置的确定性映射。原案第 7.1 节只列了随机项，没提确定性要求。
  → 建议：种子字符串 + 字段级 PRNG 子流 + 定点整数运算 + 版本号（§2.1.4）。验收标准：1000 个种子在两端生成配置的 diff = 0；同版本重放结果 diff = 0。

- [P1] **规则变异的乘法叠加会爆炸，原案没有预算概念。**
  → 为什么：「裸卖空」「无涨跌停」「情绪市场（冲击敏感度×2）」同时出现时，C 路径的做空收益是乘性放大而非加性，理论收益可到基准的 2-3 倍，「垄断判定」在第 2 天就能被触发，整个 Demo 只剩一种玩法。
  → 建议：变异抽取加**预算天花板**（单路径 |Σf| ≤ 3，全局 Σ|f| ≤ 6）+ 互斥组（§2.1.3）。被预算拒绝的抽取直接丢弃，不重抽，保证规则组合的「总能量」有上界。

- [P2] **「情报公开化」这类变异会直接废掉 Demo 强制实现的「情报公司」。**
  → 为什么：Demo 必须实现情报公司（验证信息博弈），而 R-M04 让所有内幕 6h 后公开，等于把情报公司的时间差窗口压到 0；同类还有 R-M23（绝密情报可直接买，价高者得）会挤压「情报作为拍卖品」的设计。
  → 建议：给规则变异加**系统三明治检查**：若某变异会使 Demo 必选系统（情报/市场/种植）的有效性降到 40% 以下，则本局不出该词条。R-M04、R-M23 在 Demo 局内权重置 0，只在完整赛季启用。

- [P2] **NPC 破产太快会掏空生态，破产太慢会让玩家无成就感。**
  → 为什么：3 天局里 NPC 是唯一的博弈对手。若鹰派 NPC 第 2 天就爆仓，玩家第 3 天没有交易对手，垄断判定变成对空气；若 NPC 打不死，玩家拿不到「收购」这个核心验证环节。
  → 建议：给 NPC 破产概率设目标区间 **20-30%**（相对「玩家不打压」的自然情况），并配「怜悯闸门」和「资产接管」而非「凭空补位」（§2.3.4）。

- [P2] **跨局保留「图鉴」三个字无法实现，且没说清什么绝对不能留。**
  → 为什么：光说保留图鉴，工程上无法判断「天赋解锁了要不要给开局点」「见到过的规则变异下一局要不要多出现」。这些模糊地带是数值碾压的入口。
  → 建议：给出**白名单 + 黑名单 + 硬约束**（§2.4）。白名单 7 项、黑名单 5 项、加一条可测的硬约束（跨局因素对单局终局净值加成 ≤ +5%）。

- [P2] **天赋「必胜」风险没有任何评级，尤其史诗卡。**
  → 为什么：「市场冻结 3h」「逼仓专家 +25% 平仓成本」「仓储扩容 ×3」这类卡在特定规则组合下会形成不可逆的优势，直接违反原案 §12.1 第 5 条。
  → 建议：每个天赋带**必胜风险评级**（低/中/中高/高/极高），高及以上必须配「自我限制条款」（锁自己也锁别人、触发上限、成本递增），并设胜率复核指标：拥有该天赋的玩家单局胜率 ≤ 基准 +12 个百分点（§2.2.4）。

## 2. 丰富后的设计

### 2.1 A. 世界种子生成器

#### 2.1.1 种子字符串格式

```
GG-K7M3X9QP
│   └────── 7 位内容码（Crockford Base32，去除 I L O U，共 31 字符集）
└────────── 前缀 GG（《割不割》），固定；末 1 位为校验位（前 7 位的 CRC-5，检出全部单字符错误与 96% 双字符错误）

玩家可见摘要（开局弹窗 + 分享卡）：
种子 GG-K7M3X9QP ｜ 世界：3作物·动荡年·裸卖空+仓储减半·无涨跌停 ｜ NPC×1·鹰派 ｜ 难度 A✚1 B-1 C✚2 D0
```

- 手输入一律归一化：转大写、去分隔符、O→0、I/L→1。
- 完整版额外支持**每日挑战种子**（`DAILY-2026-10-07`，由日期派生，全局同种子）与**自定义房间种子**（房主输入，好友同世界）。

#### 2.1.3 规则变异词条表（24 条）

**幅度口径**：对某路径标 `+n`/`-n`，n ∈ [-3,+3]，表示该路径的**相对达成率偏移**，换算 `×[1 + 0.08n]`（+1 → ×1.08，+3 → ×1.24）。这是提议值（待校准），需在纸面模拟 200 局后回归拟合。

**预算约束（硬）**：同一条词条所影响的路径之和 `Σ|f|` 计入全局预算；**单路径 |Σf| ≤ 3**，**全局 Σ|f| ≤ 6**，超限则丢弃本次抽中的词条（不重抽）。互斥组内最多同时出现 1 条（信息组最多 2 条）。

#### 2.1.4 生成算法（伪代码）与可复现性要求

```
# ---------- 常量 ----------
SEED_VERSION = "GGv1"          # 任何权重/字段变更必须升版本；旧版本保留回放函数
FIELDS = ["F1","F2","F3","F4","F5","F6","F7","F8","F9"]   # 顺序固定，禁止并行打乱

fn fnv1a64(s):                  # 64 位 FNV-1a，纯整数
    h = 0xCBF29CE484222325
    for b in utf8(s): h = (h XOR b) * 0x100000001B3 mod 2^64
    return h

class Rng:                      # 每个字段一个独立实例
    def __init__(self, h): self.s = h
    def u32(self): return (splitmix64(self.s) >> 32) & 0xFFFFFFFF   # splitmix64 省略
    def pct(self): return self.u32() % 10000      # 万分位概率，整数，禁止 float
    def pick_weighted(self, table):               # table: [(item, weight)] 权重为整数
        total = sum(w for _,w in table); r = self.u32() % total; acc = 0
        for item,w in table:
            acc += w
            if r < acc: return item
        return table[-1][0]

fn generate_world(seed_str, version=SEED_VERSION):
    S = normalize(seed_str)                       # 大写、去分隔符、O->0 I/L->1
    assert crc5(S[3:10]) == S[10]                 # 校验位
    H = fnv1a64(version + "|" + S)
    sub = { f: Rng(splitmix64(H XOR fnv1a64(f))) for f in FIELDS }   # 字段级子流
    cfg = {}
    cfg.crops      = pick_crop_pool(sub["F1"])            # F1
    cfg.map        = gen_map(sub["F2"], cfg.crops)        # F2
    cfg.mutations  = pick_mutations(sub["F3"], cfg)       # F3，含预算与互斥检查
    cfg.event_pool = pick_event_profile(sub["F4"])        # F4
    cfg.npcs       = pick_npcs(sub["F5"])                 # F5
    cfg.price_bias = { c: 0.85 + 0.03*sub["F6"].u32()%11 for c in cfg.crops }   # F6
    cfg.auction    = pick_auction(sub["F7"])              # F7
    cfg.intel      = pick_intel_market(sub["F8"])         # F8
    cfg.starter    = pick_starter_pack(sub["F9"])         # F9
    cfg.path_bias  = sum_path_bias(cfg.mutations)         # f(A..D)，供 §2.5 补偿
    cfg.adapt_pack = world_adapt_pack(cfg.path_bias)      # L1 对称补偿
    return cfg

fn pick_mutations(rng, cfg):
    n = rng.pick_weighted([(0,20),(1,45),(2,27),(3,8)])
    pool = [m for m in MUTATIONS
            if m.demo_allowed or not is_demo()]        # Demo 局过滤 R-M04/R-M23
    chosen, budget_path, budget_total = [], {}, 0
    for attempt in range(16):                          # 拒绝采样上限，固定为 16
        if len(chosen) == n: break
        m = rng.pick_weighted([(x, x.weight) for x in pool if x not in chosen])
        if violates_mutex(m, chosen): continue         # 互斥组检查
        np_ = { p: budget_path.get(p,0) + m.f[p] for p in "ABCD" }
        if any(abs(v) > 3 for v in np_.values()): continue
        nt = budget_total + sum(abs(x) for x in m.f.values())
        if nt > 6: continue
        chosen.append(m); budget_path = np_; budget_total = nt
    return chosen                                      # 超限即少给，不强制补足 n
```

**可复现性要求（7 条硬性）**

| # | 要求 | 验收 |
|---|------|------|
| C1 | 所有概率/权重为**定点整数**（万分位），抽取路径中不出现浮点比较 | 代码审查 + 单测：两端 hash 相同 |
| C2 | 每个字段独立子流（`H XOR fnv1a64(field)`），字段间无共享状态 | 改造 F7 不影响 F1-F6 的结果 |
| C3 | 遍历顺序固定：FIELDS 用数组不用字典；拒绝采样成功即 break | 单测：同种子 1000 次生成，配置 diff = 0 |
| C4 | 版本号写入种子与存档；权重调整 → 升 `GGv2`，`GGv1` 回放函数保留 | 旧存档不因平衡性改动而改变世界 |
| C5 | 种子只存字符串，**不存配置快照**；配置永远由算法还原 | 数据库无 world_json 冗余字段 |
| C6 | 校验位检出全部单字符错误、≥96% 双字符错误 | 手抄种子错误率实测 <5% |
| C7 | 客户端可本地预生成（用于分享卡预览），但**服务端为准**；不一致时以服务端重算 | 分歧率 = 0（C1-C3 保证） |

```
                 皮包公司:["F"], 制造公司:["G","M"], 金融公司:["M"] }
PATH_AFFINITY = { A:"G", B:"F", C:"M", D:"G/M/F 全系" }

def roll_three(player):
    pool = [t for t in ALL
            if t.id not in player.owned                       # 排除已拥有
            and t.precond_met(player)                         # 前置满足（含世界条件：无拍卖场次则 F03 出池）
            and not t.requires_world_feature_missing(world)]  # 世界层面不可达的直接剔除
    for t in pool:
        if t.upgrade_of(player): t.weight_bonus = 3.0         # 已有 I 级 → 只推 II 级
    picks = []
    # 槽位 1（必得）：本系核心 —— 从 COMPANY_MAIN[player.company] 抽 1
    picks += weighted_pick(pool, scope=COMPANY_MAIN[player.company], n=1)
    # 槽位 2（必得）：路径匹配 —— 按 24h 行为分 argmax(A/B/C/D) 对应的系抽 1
    picks += weighted_pick(pool - picks, scope=PATH_AFFINITY[player.top_path], n=1)
    # 槽位 3（自由）：全池加权抽 1
    picks += weighted_pick(pool - picks, n=1)
    # 软保底（保底计数器跨局不保留）
    if player.no_rare_streak >= 2 and not any(t.rarity != 普通 for t in picks):
        picks[-1] = weighted_pick(pool - picks, scope=["稀有","史诗"], n=1)[0]; player.no_rare_streak = 0
    else:
        player.no_rare_streak = 0 if any(t.rarity != 普通 for t in picks) else player.no_rare_streak + 1
    # 废卡校验（强制）；live = 效果在本局当前世界/局面下 24h 内能产生可观测差异
    tries = 0
    while live_count(picks) < 2 and tries < 8:
        picks[-1] = weighted_pick(pool - picks, n=1)[0]; tries += 1
    assert 1 <= live_count(picks) <= 3 and cross_series(picks) <= 1
    return picks
```

#### 2.3.2 统一决策主干（伪代码）

```
# P = {risk, aggr, info, patient, revenge}  ∈ [0,1]
# 每 30min 一个 tick（Demo 提议值）；离线时段每 2h 补算一次，动作量 ×0.5

def npc_tick(npc, world):
    st = observe(npc, fidelity = npc.P.info)     # 观察精度受信息敏感度影响
    cands = []
    if st.idle_plots > 0:
        cands.append(Plant(crop=argmax_ev(st, world), plots=st.idle_plots))
    for c, qty in st.inventory.items():
        sell_threshold = 1.0 + 0.25*(1 - npc.P.patient)      # 耐心 0 → 涨 25% 就卖
        if price(c) >= base(c) * sell_threshold:
            cands.append(Sell(c, ratio = 0.3 + 0.5*npc.P.aggr))
    tgt = pick_target(npc, world)
    if tgt and attack_ready(npc, tgt, world):
        cands.append(Attack(tgt, tool = best_tool(npc, world)))
    if st.cash < st.burn_rate * 6:                            # 生存线
        cands.append(Borrow(amount = st.burn_rate * (6 + 12*npc.P.risk)))
    if st.inventory_total > st.capacity * 0.9 and world.rules.has("仓储减半"):
        cands.append(Dump(ratio = 0.6))                       # 蠢事：仓储减半时慌乱抛售
    cands.append(Wait())
    return argmax(cands, key=lambda a: utility(a, npc.P))

def utility(a, P):
    u  = a.expected_value_norm                       # 期望收益 / 自身净值
    u -= (1 - P.risk)  * a.drawdown_risk   * 2.0     # 保守人格对回撤惩罚翻倍
    u += P.info        * a.information_edge * 0.8
    u -= (1 - P.patient)* a.time_cost      * 0.5
    u += P.revenge     * a.revenge_bonus   * 1.2
    u += P.aggr        * a.market_impact   * 0.6     # 攻击性偏好「能打压别人」的动作
    return u

def attack_ready(npc, tgt, world):
    if world.elapsed < world.aggro_gate: return False        # Demo：D2 12:00 前不主动攻击
    if tgt.net_worth < world.mercy_floor: return False       # 怜悯闸门（§2.3.4）
    if npc.cash < tgt.attack_cost * (1.5 - npc.P.risk): return False
    return rng(npc.stream).pct() < npc.P.aggr * 5000         # 万分位，攻击 0.65 → 32.5%/tick

def on_attacked(npc, by, magnitude):
    npc.grudges[by] += magnitude * npc.P.revenge
    if npc.grudges[by] > 0.6 - 0.3*npc.P.revenge:            # 报复心越高，阈值越低
        npc.queue(Retaliate(by, delay = rand(2h, 24h) * npc.P.patient))
```

### 2.4 D-1. 肉鸽与放置的冲突：跨局保留什么

#### 2.4.1 冲突的本质

- 放置的心理契约：**投入会累积**。肉鸽的心理契约：**每局归零，靠技术/运气**。原案把两者放在同一个「时间轴」上：3 天局里，玩家刚把地块升到 Lv2、天赋点到 5 个，就重开。
- 结论（取舍）：**不靠「保留强度」来安抚放置玩家，靠「保留广度 + 账户层可见增量」**。单局的一切数值归零，但玩家的**可选空间每局都在变大**，且每局都有 3 个以上「账户层可见增量」。

#### 2.4.2 跨局保留白名单（7 项，全部要求「不改变单局数值上限」）

| # | 保留项 | 保留什么 | 对单局强度的最大影响 |
|---|-------|---------|-------------------|
| K1 | 图鉴 | 已见过的作物/事件/规则变异/公司类型/结算提名，解锁图鉴文字与插画 | 0（纯展示） |
| K2 | 天赋解锁 | 把天赋从「未解锁」变「可入池」；**抽取次数不变（仍 10 次/局）** | 池子从 12 → 27，多样性 +，单次抽取强度不变 |
| K3 | 成就 | 称号、徽章、头像框、结算画面皮肤 | 0 |
| K4 | 好友关系 | 固定队伍、同学的赛季记录、观战权限 | 0 |
| K5 | 恩怨账本 | NPC 与玩家的「他坑过我」记录 → 只影响 NPC 的攻击**优先级**与台词，不加减数值 | 0 数值（优先级变化） |
| K6 | 活跃点 | 每日低保累积的活跃点，只能兑换：外观、天赋重抽次数（≤2/局）、种子自定义（1 次/局） | ≤ +5%（重抽次数是最强项，见硬约束） |
| K7 | 种子收藏 | 收藏/分享的世界种子与本局最佳战绩，可创建同种子房间 | 0 |

#### 2.4.3 硬约束（可测）

> **任何跨局因素对单局最终净资产的贡献 ≤ +5%。**

计算方式：设 `终端净值(全部跨局加成)` 与 `终端净值(全部跨局加成关闭)` 为同一策略在同一世界下的两次模拟，比值必须 ≤ 1.05。当前设计下的估算：K6 的 2 次额外重抽 ≈ +1.8%（按重抽提升抽取质量的经验值 0.9%/次）；天赋池扩大 ≈ ±0；其余 0 → **合计 ≈ +1.8%，满足约束**。若未来新增任何跨局项，必须重跑该指标。

| # | 反例 | 破坏机制（数值推演） | 结论 |
|---|------|-------------------|------|

### 2.5 D-2. 公平性：随机世界规则如何不决定胜负

#### 2.5.1 问题定位

规则变异会直接改写路径难度：本局无 R-M01「裸卖空」→ C 路径缺少核心工具；本局抽到 R-M06「仓储减半」→ C 路径的囤货逼仓闭环断掉。R-M11「病害年」+ R-M13「保险缺失」→ A 路径连续两次打击。

**接受前提**：随机必然改变难度。目标不是「难度相等」，而是「**每个玩家在同一世界里仍有可打的路径，且单局难度差异被记录与补偿**」。四条补偿机制，从粗到细。

#### 2.5.2 L1 世界适应包（对称补偿，开局一次性）

1. 计算 `f(A)..f(D)` = 所有变异对四路径的幅度和（范围 [-3,+3]）。
2. 取 `fmin = min(f)`, `fmax = max(f)`，`spread = fmax - fmin`。
3. 发**全体玩家**同一份资源包（不给特定路径，避免逼玩家选路）：

| 条件 | 适应包内容 | 理由 |
|------|-----------|------|
| 所有 f ≥ -1 | 无补偿 | 世界温和 |
| fmin ∈ [-2,-1) | 现金 +120（= 初始现金 15%） | 微小补偿 |
| fmin ∈ [-3,-2) | 现金 +200 + 仓储 +20% + 全作物种子各 1 批 | 中度补偿 |
| spread ≥ 4（世界极端偏斜） | 上档 + **1 次额外天赋抽取**（在 Lv2 时生效） | 极端世界需 Build 空间 |

示例：本局含 R-M01(+2C)、R-M06(-2C)，则 f(C)=0、f(A)=-1、f(B)=+1、f(D)=0 → fmin = -1 → **发 120 现金**（尽管 C 被对冲了，A 被削了，也一起补）。

#### 2.5.3 L2 天赋池自适应（按世界规则剪裁）

抽取时（§2.2.3）按 `f` 调整权重，规则极简：

| 情形 | 处理 | 具体例 |
|------|------|-------|
| 变异已提供某工具 | 对应天赋**权重 ×0.4**（重叠，不叠加收益） | 有 R-M01（裸卖空已开放）→ M03 裸卖空权重 32 → 13 |
| 变异削掉某路径 | 该路径**替代天赋**权重 ×1.8，并投放 1 张**局内专属卡** | 无 R-M01（f(C) 缺做空）→ 投放「**有货卖空**」：借货做空，手续费 +50%，做空量上限 8% 流通量；同时 M04/M07 权重 ×1.8 |
| 变异改写成本结构 | 投放对冲卡 | R-M03 双倍地租 → 投放「**地主议价**」：地租 -40%，持续到第 3 天 |
| 变异抬高生存风险 | B 路径补强卡权重 ×1.5 | R-M21 无破产保护 → F06 债务重组权重 ×1.5 |

专属卡**只在本局可用、不进跨局池**（不破坏 §2.4 白名单），每局最多 2 张。

#### 2.5.4 L3 多人局路径配额与 BP（完整版）

- **L3 多人局路径配额与 BP（完整版，12 人局）**：每路径软上限 3 人（= 12/4 均衡值）。第 4 人选择该路径时弹窗提示「本局该路径已有 3 人，竞争度 1.8×」，可继续（不禁止），但获得**对称补偿 200 现金**（不是独占补偿）。
- 开局后 10 分钟为「BP 阶段」，可在公司类型间**免费**改选 1 次（防止选完就发现世界不对）。
- 同种子房间的排行榜**只在同种子组内比较**，跨种子只显示「世界难度分」（用 spread 与 fmin 合成，0-10 分），避免用不同世界的净值直接比高低。

**世界难度分公式（0-10）**：`DIFF = clamp(5 + 1.2*spread + 1.5*(-fmin) , 0, 10)`；spread=4、fmin=-3 → 10（极端局），spread=0、fmin=0 → 5。

#### 2.5.5 L4 局内动态补偿（落后救济）

| 项 | 规则 |
|----|------|
| 触发条件 | 第 2 天 00:00 起，某玩家净值 < 全场中位数 × 50%，且不是「刚破产」状态 |
| 发放 | 「翻盘券」×1：二选一 —— (a) 一次免手续费大额交易（不限量）；(b) 一条准确率 90% 的内幕情报 |
| 硬上限 | **1 张/局**；不发给净值 ≥ 中位数的玩家；不发给已达成任一胜利路径判定的玩家 |
| 发放次数上限 | 全场每局最多发 2 张（超过 2 人落后时按净值升序给最落后 2 人），避免全员躺平 |
| 反滥用 | 若玩家在 12h 内主动把资产转移给他人（含皮包公司），取消资格并记录异常日志 |

**关键取舍**：L4 是唯一「给特定玩家」的补偿，所以它必须**只给一次、只给最落后、只给非主动落后**。它不是平衡器，是防劝退阀。

**落地检查表（提议值）**：① 任意世界下四路径中至少 2 条「可打」（f ≥ -2）——覆盖 100% 种子空间，抽样 10,000 个种子验证；② 单局 spread ≤ 5——≥95% 的世界满足，超限世界只出现在 DIFF ≥ 8 的房间；③ 开局弹窗必须显示世界摘要（含 f 值箭头），玩家可主动拒绝 1 次世界（1 次/账户/天）。

### 2.6 E. 失败与重开

#### 2.6.1 三种结局与重开流程

| 结局 | 触发 | 本局处理 | 账户层结算 | 重开流程 | 遗产 |
|------|------|---------|-----------|---------|------|
| **破产** | 负债率 >100% 且无法融资（R-M21 时立即） | 经济行为立即停止；资产进入拍卖池（或按 R-M22 保留 30%） | 本局见到的所有词条入图鉴；解锁「破产者」成就；结算给「最悲情破产者」提名 | 结算画面 → 图鉴解锁动画 → 生成新种子 → 选公司 → 开局 | **无遗产** |
| **被收购** | 破产后资产被某玩家/NPC 以折价买下并接管 | 公司主体转移；你的账户进入「复仇待机」 | 图鉴 + 「被收购」成就 + 记录收购方 | 立即解锁「**复仇开局**」按钮（下一局可用）；也可选择普通重开 | **有**（见 §2.6.2） |
| **通关** | 达成 C 垄断 或 赛季结算判定为首席 | 本局正常结算；垄断资产不带走 | 图鉴 + 「市场霸主」称号 + **解锁 1 个新天赋进池**（K2） | 结算颁奖礼 → 新种子 → 开局 | **无遗产，但解锁 1 个池外天赋** |

**结算仪式最小集（3 天 Demo）**：数据结算 → 首席/称号 → 提名（≥2 个必发）→ 账户层增量展示（「本局你解锁了 3 个新词条、1 个天赋」）→ 新种子摘要 → 开局。整个流程目标时长 **≤60 秒**，账户层增量必须在**重开前**展示（这是让玩家接受「归零」的关键）。

#### 2.6.2 复仇开局遗产（数值）

| 遗产项 | 数值 | 上限 | 说明 |
|-------|------|------|------|
| 现金继承 | 上局净资产 × **12%** | **300**（= 初始资产 30%） | 上限硬顶，与上局资产无关 |
| 天赋继承 | 自选 **1 个**已点天赋，开局即拥有 | 1 个 | 不占抽取次数；若该天赋前置未满足，自动降级为「前置视为满足」 |
| 仇敌档案 | 收购方 **1 个确定弱点**（如「集中持仓辣椒 62%」「负债率 71%」「第 3 天有大额应付」） | 1 条 | 只给客观数据，不给策略建议 |
| 起始地块 | 与普通开局相同（4 块） | — | **不加地块**（地块是最强资产，会让复局差异膨胀） |
| 遗产总强度预算 | 现金 ≤300 + 天赋 1 + 情报 1 | 折算 ≈ 初始资产 **30%** | 与「普通玩家 1000 + 1 免费抽取」相比，约 +28% 起点 |

**遗产不累积规则（防养猪）**

1. 连续被收购：遗产**不叠加**，始终是「12% / 上限 300」。
2. 复仇开局若再次被收购：**遗产清零一次**（下一次复仇开局 = 12% / 上限 150），惩罚「靠遗产躺赢再被吃」。
3. 复仇开局若通关：遗产归零，下一局按普通开局（避免「复仇 → 变强 → 更强」的螺旋）。
4. 故意挂机送死的检测：若上局最后 12h 内无任何交易/操作且净值为全局最低，遗产减半（150）。

#### 2.6.3 如何避免复仇者变成无脑碾压

| 机制 | 参数 | 作用 |
|------|------|------|
| 遗产总量硬顶 | 300 现金 + 1 天赋 + 1 情报 | 相对普通开局（1000 + 1 抽取）只强约 28%，**不是碾压级** |
| **复仇者标记（公开代价）** | 第 1 天全程公开显示「复仇者」标记；NPC 与玩家的攻击性对其 **×1.3** | 强度换仇恨：你被全场盯上 |
| 天赋继承不可叠加 | 只有 1 个，不随复仇次数增长 | 防止「被收购 5 次 = 自带 5 天赋」 |
| 情报一次性 | 1 条，且只反映收购方的 1 个客观弱点 | 不给「全图透视」 |
| 胜率目标（设计护栏） | 复仇开局玩家胜率 **22-25%**（6 人局基准 16.7%，即高出约 6-8pp），而非 30%+ | 明显优势但不碾压；超出 27% 即削减遗产百分比 |
| 收购方收益上限 | 收购方从被收购者处获得的资产**按其净值的 60% 折价计价**（不是 100%） | 防止「收割复仇者」变成第二波滚雪球 |
| 结算提名对冲 | 复仇者无论胜负都获得「冤有头债有主」提名（叙事价值） | 让复仇本身有回报，而不是必须赢 |

## 4. 待决问题清单

### Q-RGN-01：3 天 Demo 是否强制开启规则变异？
- **为什么必须人定**：这决定 Demo 能否验证「肉鸽多样性」，但同时决定新手第 1 局是否被劝退。是产品判断不是数值判断。
- **推荐默认**：强制开启 **1 条低风险词条**（只从权重 ≥10% 的普通词条中抽，排除 R-M08/R-M17/R-M21/R-M11）。玩家能看到「世界不同」，但不会因此输。
- **备选 A**：0 条（Demo 完全标准化）。后果：多样性卖点无法验证，需要靠后续测试补证，但新手留存更高。
- **备选 B**：1-3 条全随机。后果：约 20% 的 Demo 局会出现极端世界（DIFF ≥ 8），新手流失且无法判断流失原因。
- **推荐理由**：Demo 的目的是验证「种地→市场→打压→收购」链条，不是验证肉鸽平衡；用 1 条低风险词条做最小暴露，成本最低。

### Q-RGN-02：天赋是否跨局解锁（抽取池增长）？
- **为什么必须人定**：这是「跨局保留什么」的核心，直接决定 §2.4 白名单的形态，且影响付费/留存模型（若未来考虑商业化）。
- **推荐默认**：**是**，但只解锁「可入池」（K2），不增加抽取次数。初始池 12 个（每系 4 个：各系前 4 个普通/稀有），完整 27 个靠在局内见到/达成条件解锁。
- **备选**：全部 27 个从第 1 局就可抽。后果：新玩家第 1 局就可能抽到史诗卡，Build 感知强；但「解锁」的账户层增量消失（每局少 1 个可见增量，违反 §1 中「每局 ≥3 个账户层增量」的硬指标）。
- **后果量化**：选择「默认」时，正常玩家约 **6-9 局**解锁全池（每局平均解锁 2-3 个），与「4-6 周赛季」的节奏匹配。

### Q-RGN-03：复仇开局是否允许在多人（含真人）局使用？
- **为什么必须人定**：涉及真实社交关系与原案 §12.2「避免关系破裂」的红线，是社群政策问题。
- **推荐默认**：**允许**，但必须公开「复仇者」标记 + 攻击性 ×1.3；且被复仇者会收到系统提示「本局有玩家对你持有仇敌档案」。
- **备选**：复仇开局仅限单人 vs NPC 局。后果：社交冲突归零，但「同学之间互坑」的核心体验也被削弱一半。
- **后果**：公开标记会把一部分复仇转移到「全场围观」，这既是戏剧性来源，也是社交风险来源——需要运营侧准备「和解」入口（结算时一次互相点赞抵消恩怨）。

### Q-RGN-04：同种子对局是否作为正式玩法（每日挑战 / 房间）？
- **为什么必须人定**：这决定种子生成器是否需要公网可验证的确定性（C1-C7 全套），以及是否需要反作弊（同种子最优解会被外部工具算出并传播）。
- **推荐默认**：**是，但首期只开「好友房间」（自定种子，不排名）**；每日挑战延后到完整版，且每日挑战使用独立种子空间 + 服务器独占计算，防提前破解。
- **备选**：不做同种子。后果：确定性要求降级为「只需服务端可复现」，可省 1-2 周工程；但失去「和同学同一局比高下」的核心社交卖点。
- **风险提示**：同种子的最优解一旦被算出来，「世界随机」的乐趣会迅速退化为「抄作业」。

### Q-RGN-05：NPC 破产后是否立刻补位新 NPC？
- **为什么必须人定**：影响生态密度与叙事基调（「破产后市场变冷」是特色，还是缺点）。
- **推荐默认**：**不补位**。破产 NPC 资产进入拍卖/被收购，市场参与者变少，第 3 天世界变冷——这是叙事素材（对应提名「泡沫制造机」）。
- **备选 A**：立即补 1 个新 NPC（初始净值按全场中位数）。后果：市场始终保持博弈密度，但「破产」失去后果感，玩家的「打压 → 收购」成就感被稀释。
- **备选 B**：破产 NPC 以「债权人代理人」身份继续出现（只有台词，不参与交易）。后果：叙事保留、市场密度略降——**这是推荐方案的增强版，建议直接采用**。
- **Demo 特别说明**：Demo 只有 1 个 NPC，若它第 2 天破产，第 3 天无对手 → 必须在 Demo 期关闭「NPC 自然破产」（硬性保底：现金低于生存线时自动获得 1 次免息展期），把「NPC 可被击败但不会自杀」写进 Demo 的强制规则。

### Q-RGN-06：规则变异的数量上限与互斥关系是否对玩家公开？
- **为什么必须人定**：透明化会改变玩家策略（知道「本局最多 3 条、某个组合不可能出现」），不透明则玩家抱怨「随机不公平」。
- **推荐默认**：**公开数量上限与互斥组名称，不公开权重与幅度数值**。开局摘要显示「本局 2 条变异」，图鉴里可查「本局未出现的变异」。
- **备选**：完全公开（含 f 值精确数值）。后果：高端玩家会做最优解，但「随机的是机会」的探索感下降；同时因为 f 值精确，玩家可以精确计算是否该重掷世界。
- **后果**：默认方案让玩家能感知「世界被约束过」，是公平性的心理基础，成本仅为 1 张说明表。

### Q-RGN-07：软保底进度是否对玩家可见？
- **为什么必须人定**：可见 → 玩家会在保底触发前攒着不抽（策略化），不可见 → 玩家无法感知系统在帮他（第三方的信任问题）。
- **推荐默认**：**不可见进度，但触发时给一次显式动效**（「命运之手」提示，不解释机制）。原因是本作的抽取次数极少（正常一局 5 次），保底是「避免坏体验」而非「可规划资源」。
- **备选**：完全可见（显示「再抽 1 次必出稀有」）。后果：玩家会把抽取时机与保底绑定，可能产生「故意在第 2 次不抽」等反直觉行为。
- **代价**：不可见时，若玩家整局没出稀有，会归因为「运气差」而非「系统坏了」——这是可接受的，因为保底存在的目的就是不出现这种情况。

### Q-RGN-08：天赋重抽的收费与上限？
- **为什么必须人定**：重抽次数直接改变单局强度（§2.4 硬约束 +5% 的唯一来源），也影响「氪金/活跃点兑换」的边界。
- **推荐默认**：**每局第 1 次免费，之后 60/90/135/203 现金递增**；活跃点（K6）每局最多兑换 2 次免费重抽；**每局重抽总次数上限 4 次**。
- **备选 A**：完全免费无限重抽。后果：玩家会刷到满意，3 选 1 的决策价值归零，且 §2.4 的 +5% 硬约束被突破（无限重抽 ≈ 自由选择）。
- **备选 B**：不允许重抽。后果：出现「三张废卡」时玩家只能吞下，挫败感强；配合 §2.2.3 的三重约束，这种情况概率已降到 <2%，但仍是坏体验的来源。
- **后果核对**：默认方案下，跨局因素（2 次免费重抽）对终局净值的贡献 ≈ +1.8% ≤ +5%（满足 §2.4.3）。

### Q-RGN-09：Demo 的 NPC 是否允许真人扮演（AI 兜底）？
- **为什么必须人定**：这是资源问题（找不找同学当托）也是效果问题（真人比 AI 更像人，但不可复现、不可自动化测试）。
- **推荐默认**：**先 AI，保留真人接管开关**。AI 自动化测试是平衡性校准的唯一手段（100 局模拟必须能跑），真人扮演可作为「惊喜局」（比如运营同学在第 1 天扮演，第 2 天交给 AI）。
- **备选**：Demo 阶段全部真人。后果：平衡性无法量化验证，玩家胜率假设（§2.3.4 的 45-55%）无法测量，且 Demo 必须凑齐人手才能跑。
- **代价**：AI 人格再细腻也有上限；建议 Demo 目标设为「玩家能给 NPC 起外号」（§1 评审项），而不是「以为是真人」。

### Q-RGN-10：破产玩家能否在本局内以「债权人身份」有限复活？
- **为什么必须人定**：这是游戏体验与「破产必须有后果」之间的取舍，且影响局时长（3 天局里玩家破产后可能还有 30h 没事干）。
- **推荐默认**：**允许「债权人旁观 + 1 次投票权」**：破产玩家可在拍卖中作为债权人投票决定资产归属（权重按债权比例），但不能交易、不能种植。这保证「破产后有 30h 没事干」的挫败感被降到可接受。
- **备选 A**：完全出局（只观战）。后果：破产玩家流失率极高，且 3 天局的「第 2 天破产」概率不低（尤其抽到 R-M21 无破产保护）。
- **备选 B**：允许有限交易（僵尸公司）。后果：「破产」这个结局失去意义，且债权人复活会干扰幸存者的垄断判定。
- **判断依据**：Demo 观察「第 2 天破产的玩家第 3 天是否还会回来」，若回来率 <30%，就必须采用备选 A 之外的方案。

### Q-RGN-11：结算称号是否标注「逆风 / 顺风」含金量？
- **为什么必须人定**：这是把「世界随机带来的不公平」转化为荣誉的关键设计，但会引入叙事复杂度，也是原案 §8「不排名，叙事」的延伸还是偏离，需要拍板。
- **推荐默认**：**标注，但不做数值奖励**。达成路径时若该路径 f < 0，称号带金边并附一句「逆风」（如「农业大亨（逆风）」）；若 f > 0 不加标注。
- **备选**：不标注。后果：抽到有利世界的玩家被质疑「运气好赢的」，无法自证；标注是低成本（1 个字段）的公信力机制。
- **后果**：标注让「随机」从「不公平」变成「可比较」，同时可支撑完整版的跨种子排行榜（按 DIFF 分档比较）。

### Q-RGN-12：图鉴完成度是否给（哪怕外观之外的）奖励？
- **为什么必须人定**：一份奖励就可能突破「只保留广度」的原则；但如果毫无奖励，收集动机不足（图鉴完成度 100% 与 5% 的玩家体验相同）。
- **推荐默认**：**给外观与重抽次数（K6 已含），不给任何数值**。具体：完成度 25% 解锁头像框、50% 解锁结算皮肤、75% 解锁「种子自定义」1 次/局、100% 解锁独家种子前缀。
- **备选**：给数值（如完成度每 10% 给初始现金 +20）。后果：直接违反 §2.4.3 硬约束（完成度 100% = 初始现金 +200 = +20% 起点），并且会让新玩家处于长期劣势。
- **判别口诀复用**：「完成度换现金」= 强度 → 禁止；「完成度换外观/重抽」= 广度 → 允许。

### Q-RGN-13：多人局是否强制路径配额（BP）？
- **为什么必须人定**：强制配额会牺牲玩家自由（想玩 C 却被劝退），不强制则会出现「8 人全选 C」的退化局。
- **推荐默认**：**软配额 + 对称补偿**（§2.5.4）：软上限 3 人，超配者提示 + 获得 200 现金，不禁止选择；BP 阶段 10 分钟内可免费改选 1 次公司类型。
- **备选**：硬配额（超过 3 人禁止选 C）。后果：保证队伍构成健康，但玩家体验受损（「我想玩为什么不让我玩」），且在小规模同学群可能导致社交摩擦。
- **后果**：软配额的代价是极端局仍可能出现（8 人全 C），但对称补偿会让这局变成「高竞争度局」，反而是戏剧性来源。

### Q-RGN-14：NPC 恩怨账本是否跨局持久化？是否显示真人身份？
- **为什么必须人定**：涉及隐私（NPC 记仇跨局，会不会让玩家觉得被系统针对）和社交（是否暴露「谁坑过我」）。
- **推荐默认**：**跨局持久化，但只记录行为与后果，不显示真人现实身份**；账本内容仅玩家本人可见（单机视图），不公开给其他人；账本对下局的 NPC 只影响「攻击优先级」，不加减任何数值（K5）。
- **备选**：每局清零。后果：NPC 变得「无记忆」，人味打折；但玩家不会有「被系统针对」的错觉，也避免纠纷。
- **后果**：跨局记忆是「被记住的满足」（原案 §1.2）在 NPC 侧的落地；但必须给玩家一个「和解/清零」入口（例如结算时与某个 NPC 达成一笔交易即可清除该条恩怨），否则会累积成负面积怨。
