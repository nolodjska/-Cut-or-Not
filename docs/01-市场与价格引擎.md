## 0. 摘要

- **价格不是「一条线」，是三个量**：`price`（现货）、`anchor`（基本面锚）、`twap`（估值口径）。
  三者分工：现货用于成交，锚用于回归与事件，TWAP 用于算身家。混用任何一个都会被玩家套利（见 09 §2.2）。
- **价格冲击与市场深度必须拆开**：`float0`（对手盘库存）决定「你能买多少」，
  `depth`（= NPC 日吸纳 × 3.5）决定「买这些货会推多远」。混为一谈会让一次正常收成砸穿 40% 的价（09 §2.5）。
- **冲击是指数形式** `P *= exp(±η·Q/depth)`，好处是永远为正、买卖对称、可解析估算。
- **冲击会饱和**：价格越偏离锚，边际冲击越小（`×1/(1+偏离×5)`）。没有这一项，有钱玩家能把价格推到无穷。
- **价格带由阀门夹住**：下沿 0.70 倍（地板买家）、上沿 1.45 倍（进口阀门）、硬顶 1.75~2.20 倍。
  阀门是**价格阀门**，不是**供货阀门** —— 后者会变成「有钱就能无限扫货」（09 §2.9）。
- **全场唯一的外部价值注入源是 NPC 终端需求 40,000 金/天**。没有这一端，全场净资产是零和的，
  「净资产 ≥ 开局 3 倍」在数学上不可能多人达成（02 分支的关键发现）。
- **涨跌停默认开**（`rules.limitDown`），变异关掉后会变成「无涨跌停」世界，波动更大但也更容易被砸穿。
- 单次价格战的最大伤害被约束在 **±30% 量级**，这是「斗争不能太狠」的数学实现。
- 必须验算的那个问题（萝卜 2 小时周期 + 60% 门槛在 3 天局能不能垄断）：**能，但要在 3 天内反复买空对手盘**。
  实测专心囤货打法 53% 成功率、15% 出局率 —— 见 09 §3.1。

## 1. 评审：问题与风险（针对原案 §5.2 那四行字）

原案 §5.2「价格波动机制」一共四行：供需模型、随机事件、玩家影响、离线保护。
这四行在实现层面各藏着一个坑：

- **[P0] 「价格 = 基础价 × (1 + 需求系数 − 供应系数)」在数值上会变负。**
  需求系数比供应系数小 1 以上时价格直接为负。必须换成乘法形式（`exp`）并夹下界。
  → 建议：`price = max(0.5, base × 各项乘子)`，冲击用 `exp` 保证恒正。
- **[P0] 「玩家影响价格」没有给量级，等于没写。** 谁都能声称"大额交易影响价格"，
  但「多大算大额」「影响多少」决定了逼仓是否可行。**必须给出 depth 与 η，否则逼仓无法计算。**
- **[P0] 「离线时价格波动减半」无法实现。** 价格是全服共享的一个数，
  你离线时别人在线，凭什么全局波动减半？→ 修正：价格全局唯一，
  离线保护作用在**玩家自己的资产**上（离线期间你的持仓不参与结算折价、NPC 不主动攻击你）。
- **[P1] 没有手续费 → 无风险套利。** 见 §3.2 算式。
- **[P1] 没有价格带 → 一个人就能把市场推到 22 倍**（实测，见 09 §2.1）。
- **[P1] 没有做市商库存上限 → 「挂单」和「市场深度」是两套互不相干的东西，UI 会自相矛盾。**
  修正：对手盘 `mmInv` 就是唯一对手方，玩家的限价单挂在它旁边，价格穿过才成交。
- **[P2] 需求系数/供应系数没有定义由谁观测。** 是全场库存？还是当日产量？
  不同口径会得出完全不同的价格曲线，必须写死在文档里（本文件 §2.2）。

## 2. 丰富后的设计

### 2.1 三个价格量的分工

| 量 | 含义 | 用途 | 更新方式 |
|---|---|---|---|
| `price` | 现货成交价 | 一切实际成交、冲击计算 | 每 tick 噪声 + 回归 + 交易冲击 + 阀门 |
| `anchor` | 基本面锚 | 回归目标、偏离判定 | 向 `base × 事件乘子 × 舆论乘子` 慢回归（半衰期 24 h），并被交易以 40% 比例带动 |
| `twap` | 时间加权价（半衰期 6 h） | **净资产估值、结算、垄断摊牌** | 向 `price` 平滑 |

铁律：**任何"算身家"的地方只能用 `twap`**。用现货 = 允许玩家自己拉盘抬身家（09 §2.1/2.2）。

### 2.2 每 tick 的价格更新（伪代码，与 `_priceTick` 一一对应）

```
for each crop c:
  # 1) 基本面
  fundamental = c.base × c.eventMult × c.rumorMult

  # 2) 终端需求注入（全场唯一价值来源），并被基本面约束住
  injPerMin = (c.absorbDay / 1440) / c.float0
  c.anchor *= (1 + injPerMin × 0.02)
  c.anchor += (fundamental − c.anchor) × kAnchor        # kAnchor: 半衰期 24h
  c.anchor = clamp(c.anchor, fundamental × 0.55, fundamental × 1.70)   # 防无限漂移

  # 3) 随机噪声（按 dt 的平方根缩放，保证不同 tick 粒度下方差一致）
  c.price *= (1 + (rand−0.5) × 2 × c.vol × sqrt(dt/60) × 0.6)

  # 4) 向锚回归
  c.price += (c.anchor − c.price) × kPrice             # kPrice: 半衰期 14h

  # 5) 偏离越大，回归拉力越强（弹性供给/需求的现实化）
  dev = c.price / c.anchor − 1
  if |dev| > 0.20: c.price += (c.anchor×(1+sign(dev)×0.20) − c.price) × 0.02 × clamp(|dev|/0.20, 1, 4)

  # 6) 价格阀门（对称，把单次价格战伤害锁在 ±30% 量级）
  if c.price < c.base × 0.70:  c.price += (c.base×0.70 − c.price) × 0.25 ; 补极少量库存
  if c.price > c.base × 1.45:  c.price −= (c.price − c.base×1.45) × 0.60 ; 补极少量库存
  if c.price > 硬顶(1.75 或 2.20): c.price −= (c.price − 硬顶) × 0.35

  # 7) 采样 TWAP 与走势历史（每 15 游戏分钟一个点）
  c.twap += (c.price − c.twap) × kTwap

  # 8) 做市商自然补货（代表持续生产者供货）
  c.mmInv += (c.float0 − c.mmInv) × kAnchor × 0.9
  c.mmInv = clamp(c.mmInv, −c.float0×0.5, c.float0×4)
```

### 2.3 交易冲击（`_impact`）

```
冲击 imp = η × (Q / depth) × 各项天赋/政策修正
  × 饱和项：买入且价高于锚 → ×1/(1 + (price/anchor − 1) × 5)
             卖出且价低于锚 → ×1/(1 + (1 − price/anchor) × 5)
成交价：买入 P *= exp(+imp)；卖出 P *= exp(−imp)
锚同步：anchor *= exp(±imp × 0.40)        # 让打压有持久效果
```

买不到的情况：`Q > mmInv` 时直接拒绝（「市场只挂得出 N 单位」）。
这一条是逼仓机制的核心 —— **把对手盘买空，别人就买不到了**。

**算例（辣椒，基准 22，depth 1,907，η 2.5）**：

| 单笔数量 | 占 depth | 冲击 | 成交后价格 |
|---|---|---|---|
| 10 单位 | 0.52% | ±1.3% | 22.3 |
| 40 单位（一块地一次收成） | 2.1% | ±5.4% | 23.2 |
| 150 单位（一次逼仓式抛售） | 7.9% | −17.9% | 18.1 |
| 300 单位（打穿地板） | 15.7% | −32%（会被地板买家接住） | ~15.4 |

### 2.4 手续费与「无风险套利不可行」的证明

- 单边 2%（Demo）/ 3%（赛季）。双边 4%/6%。
- 往返总成本 = 双边手续费 + 买入冲击 + 卖出冲击。
- 以 40 单位辣椒往返为例：4% + 5.4% + 5.4% ≈ **14.8%**。
- 也就是说，**价差小于约 15% 的往返一定亏钱**；而价格带上下沿相距 107%，
  看似很大，但两沿之间被阀门夹住、且回归半衰期 14 小时，
  在一轮里同时抓到两沿的概率极低。
- 实测：贸易流 3 天累计中位 1.82 倍（净赚 82%），需要多次成功择时。
  这既不是白捡（无套利），也不是不可能（有正反馈）—— 正是要的手感。

### 2.5 做空（UI 里叫「借货看跌」）

| 项 | 值 | 说明 |
|---|---|---|
| 建仓押金 | 名义本金 × 150% | 另收卖出所得 |
| 借货来源 | 对手盘 `mmInv` | 规则允许裸卖空时不需要借货 |
| 借货费 | 名义 × 0.5%/天，现金支付 | |
| 被动清盘 | 价格反向 **+30%** | 押金不足以买回时，缺口转负债 |
| 平仓盈亏 | `Q × (建仓价 − 平仓价) − 手续费` | 押金在平仓时释放 |

**为什么押金是 150% 而不是 20%~35%**：后者是「维持押金率」的口径，不是建仓押金。
150% 建仓 + 反向 30% 被动清盘 → 单次最大损失约为押金的 20%，
既让看跌有真实风险，又不至于一次犯错直接出局。实测「莽撞看跌」亏钱但不会暴毙。

### 2.6 市场事件池

| 事件 | 权重 | 时长 | 效果 | 战略价值 |
|---|---|---|---|---|
| 干旱预警 | 3 | 12 h | 全场减产 20%，锚 +15% | 囤货 |
| 丰收季 | 3 | 12 h | 锚 −15% | 做空/低吸 |
| 网红带货 | 3 | 8 h | 单作物锚 +35% | 提前布局 |
| 病虫害 | 2 | 16 h | 单作物减产 50%，锚 +25% | 逼仓 |
| 政策变动 | 2 | 12 h | 手续费翻倍，锚 +5% | 压制高频交易 |
| 产业补贴 | 2 | 即时 | 每块已播种地 +250 G | 保护种植流 |
| 抢购潮 | 1 | 6 h | 单作物锚 +55% | 极端行情 |

- 触发：开局用种子预生成一张定时表（第 1 天 2 场、第 2 天 3 场、第 3 天 2 场，各 82% 概率触发）。
  预生成是**为了可复现**：同一世界种子的每局事件序列完全相同。
- 情报：内幕情报提前看到下一场事件的作物与方向（80% 准确），绝密情报 100% 准确（拍卖标的）。
- 舆论：玩家可花 200 G 把某作物锚推 ±10%（含天赋最高 ±15%），25% 概率被拆穿。
- **事件必须可被情报提前获知**，否则信息博弈这条线就没有载体。

### 2.7 泡沫度量（供结算分支判定「泡沫制造机」）

```
玩家 p 对作物 c 的泡沫 = max(price/anchor − 1)  在 p 把价格推高到 >15% 之上时开始记录
判定成立（p 是"吹泡沫的人"）：
  ① 泡沫高度 ≥ 20%
  ② 该作物价格从峰值回落 85%（即 −15%）时，p 的持仓 ≤ 峰值持仓的 30%（说明他跑了）
满足则 p.m.bubble = 泡沫高度，取全场最大者授予「泡沫制造机」。
```
实测触发率 1.4%（360 局）—— 确实稀有，配得上这个称号。

### 3.2 我给谁什么

给结算分支（END）的埋点字段（全部已在 `game/engine.js` 的 `p.m.*` 里落库）：

| 字段 | 类型 | 写入时机 | 用途提名 |
|---|---|---|---|
| `volContrib` | number | 每笔成交（`|ΔP/P| × 成交额` 累加） | 市场搅局者 |
| `harvestCredit` | number | 每笔成交（你的动作让**别人库存**缩水的金额） | 价差收割机 |
| `blessCredit` | number | 每笔成交（你的动作让**别人库存**增值的金额） | 经济命运共同体 |
| `bubble` / `bubbleArm` | number / object | 价格偏离锚 >15% 时开始记录，回落 15% 时结算 | 泡沫制造机 |
| `realized` | number | 每笔平仓 | D 综合分、A 判定参考 |
| `harvestedValue` / `harvestedUnits` | number | 每次收割（按 TWAP 计价） | 城市奠基人、产业链之王 |
| `feePaid` | number | 每笔成交 | 生态分析 |
| `dumpImpactMax` | number | 每次卖出取最大冲击 | 定海神针的「没砸过盘」判定 |
| `aggression` | number | 舆论/看跌/抛售时累加 | 定海神针（要求 =0） |
| `shellTrades` | number | 走皮包通道成交时累加 | 隐形操盘手 |
| `intelSold` / `intelCorrect` | number | 卖出情报时 | 最佳线报商 |
| `navHist` | `[[t, nav]]` | 每游戏小时 | 定海神针、最悲情退场者 |
| `pressure` | 0/1 | 出现现金流断裂或欠款时置 1 | 不倒翁（必须"有过威胁"） |
| `bankruptProx` / `bankruptAt` | number | 破产瞬间 | 最悲情退场者 |

> 注意：`harvestCredit` / `blessCredit` 是本引擎的**原创机制**，
> 05 分支原本用的是 `pair_pnl`（FIFO 平仓回合结果表）。两者口径不同：
> `pair_pnl` 只在玩家之间对赌时才有值，而本作大部分交易对手是市场本身，
> 所以改用「你的动作对其他持有者库存的影响金额」——**这个量在只有 NPC 对手时也有意义**。
> 若联机版要做精确的「谁割了谁」，需要另建配对表（见 Q-MKT-06）。

## 4. 待决问题清单

**Q-MKT-01｜日吸纳 40,000 金/天在 6 人真人局里够不够？**
必须人定：这是全场唯一的价值注入，直接决定 A 能否达成。
推荐默认 40,000（实测 4 人局下稳健打法 1.6~1.7 倍、垄断流靠控盘而非靠钱）。
6 个真人博弈时价值会被瓜分得更散，可能要提到 60,000。备选 30,000（更紧绷）。

**Q-MKT-02｜手续费 2% 是否太低（不够抑制刷量）？**
实测 2% 下往返成本约 14.8%，已经足以阻止套利。但高频小额交易仍可刷 `volContrib`
（提名「市场搅局者」的输入）。备选：3%（赛季值）或对 5 分钟内同向交易加收附加费。
推荐：Demo 保持 2%，赛季提到 3%，并且提名判定加「自成交与同 IP 全部剔除」。

**Q-MKT-03｜冲击饱和系数 5 是不是太大（逼仓手感被削弱）？**
偏离锚 20% 时冲击被削到 1/2，偏离 50% 时削到 1/3.5。
这保护了市场不被单人推到无穷，但也让「把价格拉到 2 倍」变得非常贵。
推荐保持 5；若实测逼仓手感太软，可降到 3。

**Q-MKT-04｜价格带上下沿 0.70 / 1.45 是否合适？**
03 原案说「±30%」（即 0.70~1.30）。我上沿放到 1.45，因为「网红带货 +35%」这类事件需要空间。
备选：严格 ±30%（0.70~1.30），好处是「单次伤害锁定」更硬。

**Q-MKT-05｜离线保护怎么落地？（我目前只做了"价格全局唯一"）**
原案「离线时价格波动减半」在数学上不成立（价格是全服共享的）。
我现在的处理是：价格照常演进，离线不影响别人。
但**离线玩家被 NPC 攻击**这一点还没做保护。需要你定：
① 完全不打离线玩家（最安全）；② 打但提前预警（推荐）；③ 照打（最快节奏）。

**Q-MKT-06｜要不要精确的「谁割了谁」配对账本？**
现在用「你的动作影响别人库存的金额」近似（见 §3.2 的说明）。精确做法要维护 FIFO 配对表
（05 分支的 `pair_pnl`），成本是每笔成交多一次配对计算。
推荐：Demo 用近似；联机版做精确，因为真人会追究「到底是谁割了我」。

**Q-MKT-07｜涨跌停开关的默认值？**
现状：默认**开**（30% ~ 220% 的硬顶），变异关掉后波动更大、更容易被砸穿。
推荐 Tournament（同学对局）默认开，肉鸽单人默认随机。

**Q-MKT-08｜「垄断溢价最高 1.4 倍」会不会让 C 路径顺便拿 A？**
实测：垄断流净资产中位 0.55 倍，即使乘 1.4 也远不到 2.5 倍，所以不会。
但如果未来把垄断门槛降低，这条溢价会让 C 玩家同时达成 A。
推荐：保持「垄断溢价只作用于库存估值，不作用于地租与授信」。

**Q-MKT-09｜舆论被拆穿的概率 25% 是否合适？**
04 分支建议 25%。同学之间玩，被拆穿的人会掉信誉（影响卖情报价格）。
但舆论对「市场搅局者」提名贡献很大（`aggression`），过高会抑制这条玩法。
备选：15%（更鼓励舆论战）。

**Q-MKT-10｜价格波动率（0.13/0.20/0.28）要不要随阶段递增？**
现状：全程恒定。原案 §9.1 说「第 3 周进入斗争期」应有更紧张的手感。
推荐：Demo 固定；赛季版第 3 周起波动率 ×1.3，制造「决战期」。

**Q-MKT-11｜三个价格量（price/anchor/twap）要不要暴露给玩家？**
现状：UI 显示现货、基准、估值三个数字（估值就是 TWAP）。
风险：三个价格会让新手困惑（「为什么我卖 100 单位，显示的价格和我拿到的钱不一样」）。
备选：只显示现货与「估值」，把「基准」藏起来（但情报玩法需要它）。
推荐：保留三个，但用一句话解释：`基准=长期均值 / 估值=算身家用的 / 现价=你现在真能成交的`。

**Q-MKT-12｜逼仓成功后的「恢复价格」阶段是否需要机制支持？**
原案 §5.4 第 6 步「恢复价格：垄断后恢复价格，获利」。
现状：垄断后价格自然回归锚（半衰期 14 h），不需要额外机制。
但**垄断者卖出时会自己砸盘**（冲击饱和项对卖出同样生效），
所以「恢复价格」实际上做得到，只是需要慢慢卖。这算不算「机制支持够了」需要你判断。
