## 二、为什么拆分方案必须动构建（关键约束）

`tools/build.mjs` 用正则替换**那一对**标签来内联：

```html
<script src="engine.js"></script>
<script src="ui.js"></script>
```

**拆成 N 个文件后，这对标签不再成立** → 产物会变成"只有 HTML 外壳的空包"。
（build.mjs 里恰好有自检：产物若比两个脚本之和小就报错。**别绕过这个自检**。）

### 幸运之处：engine.js 是 UMD 包装

```js
L1:  (function (root, factory) { ... })(..., function () {
L23:    const BAL = { ... };
        ...
L2699:  return { BAL, CROPS, CROP_IDS, ..., Game, Rng, ... };
L2720: });
```

工厂函数体 = 一个**普通函数作用域**。所以：
- **把工厂体切成有序片段（parts），按同一顺序拼接** → Node 与浏览器行为**完全一致** ✓
- 片段内部照旧用裸标识符（`BAL`/`Game`/`clamp`），**不需要任何重写** → 风险最低 ✓

## 三、目标结构

```
game/
  engine.js            ← 变薄：Node 聚合器（读 parts 清单 → 拼 → new Function → module.exports）
  engine.parts.js      ← 清单：**唯一顺序来源**（engine.js 与 build.mjs 都读它）
  parts/
    01-data.js         ← BAL + CROPS/PRODUCTS/CORPS/TALENTS/EVENT_POOL/LOT_POOL
    02-util.js         ← hash32 / Rng / makeSeed / clamp / money / round2
    03-core.js         ← Game 构造 / _init / rng / _ruleText / _newPlayer / _spawnPlayers
    04-ticks.js        ← advance* / _tick / _eventTick / _priceTick / _productTick /
                         _productionTick / _orderTick / _interestTick
    05-firm.js         ← consolidated / _bankruptcyTick / _navTick / _countdownTick / _end
                         + 指标（good…monoProx）+ 资产口径（nav/creditLimit/fixedAssets…）
    06-trade.js        ← _impact / _trade / quote / buy / sell
    07-crop.js         ← act + 农田/地块 动作（_a_plant…_a_upgradeStorage）
    08-market.js       ← 市场动作（_a_sell/_a_limit/_a_cancelOrder）+ §17.1 收货商 + §17.2 买家
    09-money.js        ← 钱庄/情报/谣言/看跌/皮包（_a_loan…_shellTick/_addCp）
    10-talent.js       ← 天赋/作坊/加工（_rollTalents…_craftTick）+ 收放贷/存取
    11-npc.js          ← _npcTick / _npcDecide / _npcFairValue / _npcRumor / _bankrupt
    12-auction.js      ← 拍卖全部（_queueBankruptLot…_awardLot）+ _log/_flush/_pidName
    13-settle.js       ← settle + 导出 return{...}
  ui.js                ← 同样拆（视图按页拆：农田/市场/制造/情报/钱庄/拍卖/结算/图鉴）
  index.html           ← CSS 抽成 game/style.css（build 内联），HTML 骨架留 ≤1000 行
```

**每个片段都必须在顶层语句边界切开**（不能切在函数中间）。

## 四、执行顺序（**每一步都必须先保证构建可用**）

**铁律：先把 parts 全部造好并验证，最后才换 engine.js 与 build.mjs。**
任何时刻都不能让 `node tools/build.mjs` 失败。

1. **造 parts**（faithful 抽取：从 engine.js 按行范围原样搬到 `game/parts/NN-*.js`）
2. **机械验证**（关键一步，见下节）：拼起来的 parts **必须逐字节等于**原工厂体
3. 换 `game/engine.js` → 聚合器；换 `tools/build.mjs` → 按清单拼 parts
4. `node tools/build.mjs` + **全套**（size/lint/ui-smoke/6 个测试/sim 660 局）
5. `ui.js`、`index.html` 同样流程

## 五、验证手段（不靠"看着对"）

### ① 逐字节等价（拆分是否丢东西）
新建 `tools/parts-verify.cjs`：
```
原工厂体（engine.js 去掉 UMD 头尾）= parts 按清单拼接（去掉分隔注释）  ← 必须逐字节相等
```
不等就打印**第一处差异的行号与上下文**。这是拆分安全性的**唯一硬证据**。

### ② 行为等价（拆分有没有改行为）
- `tools/sim.cjs`：**种子可复现** + **存档往返** + **不变量异常=无**
- 6 个测试全绿 + `ui-smoke` + `lint-copy`
- 对比拆分前的 660 局破产数（基线 **97/660**）

### ③ 规则守卫（长期）
`tools/size.test.cjs` 已就位 —— 以后任何文件超 1000 行都会被它拦下。
**建议把它加进提交前的必跑清单。**

## 六、并行的边界（复用本轮学到的教训）

- ✅ **可并行**：每个 subagent 造**一个 part 文件**（互不重叠的新文件）
- ❌ **不可并行**：改 `engine.js` / `build.mjs`（同一个文件，`write` 是读-改-写，会互相覆盖）
- ⇒ 分工：**subagent 并行造 parts，主控一个人做最后的换装**（第 3 步）

### 机制（为什么两边一致）

```
                    game/engine.parts.js   ← 清单（唯一顺序来源）
                            │
        ┌───────────────────┴───────────────────┐
        ▼                                       ▼
  game/engine.bundle.js                   tools/build.mjs
  .load() → new Function(UMD)             .source() → 内联进 <script>
  即 require('./engine.js') 拿到的那份     即玩家双击打开的那份
```

**Node 与浏览器跑的是同一段文本** —— 由 `engine.bundle.source()` 单一出口保证。

### 迁移期踩到的坑（均已修，写在这里免重犯）

1. **`new Function` 不是瓶颈**：一度怀疑它导致 `VirtualAlloc failed`；
   实测单独跑 `lint`/`build`/`sim` 全部通过 → **真正原因是机器上堆积了 19 个僵留 node
   进程（含一个 455 MB），可用内存只剩 4.7 GB**。**先怀疑环境，但要用“单独重跑”去证伪自己。**
2. **工具自己的 bug 比被验对象的 bug 更隐蔽**：`parts-verify` 第一版用“行数组 + 弹末尾空元素”
   比较，写出了两个**互相矛盾**的工具（一个报“少 3 行”、一个报“全部相符”）。
   改成**文本比较**后歧义消失，真实缺口只有 **1 行**（`11-intel.js` 末尾空行）。
3. **subagent 的自检会骗过它自己**：16 片里有 3 片报了“完全一致”，实际有一片少了末尾空行。
   → **必须主控独立验证**（这正是 `parts-verify` 存在的意义）。
4. **`.js` 文件的注释里不能出现 `星号+斜杠` 连写**：我把函数名清单写成 `advance*/_tick`，
   它提前关闭了注释块，直接语法错误。写函数名清单时**斜杠两侧务必留空格**。

### 并行开发复盘

- **并行有效**：16 片 = 16 个 subagent 各自写一个新文件，**零冲突**，全部成功
- **不可并行**：换装（engine.js / build.mjs）由主控一人完成
- 一个 subagent 主动提醒了「split 幻影空元素会假通过，必须比字节」，**另一个自己发现了 1 处缩进差**
  —— 这种“主动预警”比“报告成功”有价值得多。
