## 0. 前置决策：三个"钱"必须彻底分开（否则必翻车）

`docs/19` §4.10 已定死：**净资产（公司层，单主体）** 与 **身价（集团层，加权并表）** 不能同名。
UI 上三个钱数必须用**字体层级**强制区分：

| 显示名 | 归属层 | 公式 | UI 位置 |
|---|---|---|---|
| **身价** | 集团层（你） | 个人现金 + Σ(持股% × 各公司净资产) | 顶栏最大字（印章体） |
| **个人现金 / 负债** | 集团层（你） | 直接读个人账 | 顶栏次大字 |
| **公司净资产 / 估值区间** | 公司层（棋子） | `07-metrics.js` 原公式 | **只在公司卡里出现** |

**另**：项目有文案铁律 —— 现实机制可内化，但**不得把术语暴露给玩家** ⇒ 全方案采用**双名制**（见 §6）。

## 2. 层次感设计

### 2.1 主屏（总账）一屏内 6 层

| 层 | 内容 | 常驻/点进 | 权重 | 为什么在这个位置 |
|---|---|---|---|---|
| **Z0 顶栏** | **身价（印章超大字）**·现金·授信·日子·[信匣章+角标] | 常驻 | ★★★★★ | "一眼看懂钱在哪"⇒ 钱放最高处；身价是结算值，必须最大。信匣角标把倒计时钉在视线角 |
| **Z1 告急带** | 决议倒计时/要约到期/强平/关注度/评估过期 | 常驻（有内容才显） | ★★★★ | 高于资产列表：**资产不会自己少，但决议会超时弃票、要约会过期、杠杆会被强平**。红章色，一行，点进详情 |
| **Z2 控股地图** | 每家公司一张卡 | 常驻（主体，可滚） | ★★★★ | 屏幕主体。卡 = "我拥有什么"，也是进公司层的唯一门 |
| **Z3 组合摘要** | 组合总浮盈 + 今日/本季派红 | 常驻（一行，可折） | ★★★ | 一行够用；细节在「往来账」，避免挤占 Z2 |
| **Z4 进店行** | 股票行·中人行·估价单·钱柜（4 图标） | 点进 | ★★ | 低频重功能收口，把屏幕让给 Z2 |
| **Z5 底部** | **无 tab**（一级根屏） | — | ★ | 一级屏不该有 tab；tab 属于二级公司层，避免两套导航打架 |

**公司卡（Z2 单元）放 6 项**：
`公司名` · `状态章（控股/参股/举牌中/要约中）` · **持股%** · `估值区间 or 市值` · `健康度灯` · **【进入经营】/[看行情]**

### 2.2 常驻 vs 点进（判据）

- **常驻**：顶栏 4 数 + 信匣角标（含最近倒计时）+ 总账 Z1 告急带
- **点进**：往来账·派红·股票行·行市·下单·估价单·中人行·谈盘·钱柜·流水·黄历，以及**整个二级公司层**
- 判据：**"数字要跟人走"的常驻，"动作要做完跑"的点进**

## 3. 现有 7 页签怎么处理（结论：**两级导航**）

| 方案 | 判断 | 理由 |
|---|---|---|
| 替换 | ✗ | 7 页签是公司层经营的全部操作面，替换＝删游戏 |
| 并列（两套导航同屏） | ✗ | 430px 下互抢空间；"集团 vs 公司"层级错位，必迷路 |
| 变成第 8 个页签 | ✗ | **层级错误**：集团层是 7 页签的**上级**，平铺＝把爸爸塞进儿子班。且 8 tab ÷ 430px ≈ 53px/个，「拍卖/图鉴」会被挤到看不清 |
| **重构成两级导航** ✅ | ✓ | 层级正确；可扩展（第 3、4 家公司只多一张卡，不占新页签）；邮箱天然落在一级 |

**对现有代码最小侵入的落地口径**：
- **保留** `#view` + `#tabs` 原样 → 整体成为"**当前在营公司的工作台**"；
- **新增**一级根屏（总账）作为根视图；
- **顶栏加面包屑**：二级时显示 `← 集团 ｜ 坤叔·种植公司 ｜ 持股 34%`；一级时不显公司名。
- 玩家体感：**顶栏我永远是我（集团），底栏永远"这家公司"**。

## 4. 430px 可容纳性判断

可用高 ≈ 900 − 顶安全区(~48) − 底安全区(~24) ≈ **820px**；经验行高：卡 72 / 列表行 64 / 图标行 88。

| 面板 | 判断 | 依据 / 处置 |
|---|---|---|
| 顶栏（身价+3数+信匣） | ✅ | 单行 44px；身价超 7 位数用「万/亿」缩位，不换行 |
| 总账 Z0+Z1+Z2×6 | ✅ | 44+36+6×72 ≈ 512px；**加 Z3+Z4 就溢出 ⇒ 贴底、需轻微上滑** |
| 告急带 | ✅ | 一行；>3 条只显最急 1 条 + "还有 2 条"，点进信匣 |
| 信匣（会话列表） | ✅ 约 10 行 | 会话式列表天生适合窄屏，无需分页 |
| 票决（决议详情） | ✅ | ≈480px 一屏；议案正文过长需内滚 |
| 往来账（持股组合） | ⚠️ 滚动 | 每标的 1 行；>6 只必须滚动，**不做横向多列** |
| **股票行（交易所大厅）** | ❌ **必须改版** | 真机"盘口+资金条"多列在 430px 放不下 ⇒ **改"每股一卡"纵向列表**，深度阶梯改纵向堆叠，点卡进「行市」 |
| 行市（个股） | ⚠️ 分两段 | 上段价格+门槛距离条恒显；下段挂单簿**折叠** |
| 下单票据 | ✅（浮层） | 底部弹层，键盘弹起时上推 |
| 估价单 | ✅ | 区间条 + 有效期进度 + 评估师签章，天然一屏 |
| 中人行（并购台） | ⚠️ 滚动 | 标的列表滚动；反收购预警用角标不占行 |
| 谈盘 | ✅ | 三种付款做成段控件，选中才展开参数 |
| 黄历 / 流水 | ⚠️ 滚动 | 列表式天然可滚 |

**结论**：7 个"详情/表单"类可一屏；6 个"列表/行情"类必须纵向滚动；**只有「交易所大厅」必须重设计（多列表 → 卡片流）**。

## 5. 反对意见（会怎么翻车 + 改法）

1. **信息过载**：总账塞 身价+告急+6卡+组合+4进店 ⇒ 一屏装不下，"一眼看懂"变"一眼吓退"
   → **总账只留 Z0+Z1+Z2**，Z3/Z4 贴底可折；进店默认收起，只上浮"最近用过的 2 个"。
   **验收标准：竖屏第一屏内不出现第二个"钱"的模块。**
2. **层级太深**：总账→公司卡→route UI→页签 = 4 层，回一次要点 3 下
   → **记忆落点**（点公司卡直进"上次停留的页签"）+ **面包屑一次回根**；高频动作（增减持）**提到 Z2 公司卡的长按菜单**，不深入。
3. **两套导航打架**：玩家分不清"顶栏集团"和"底栏 7 页签"
   → **色与形分离**：顶栏纸底墨字（"我"），底部 tab 用**印章红/账本页边**（"这家公司"）；二级时顶栏强制显示公司名；首次进入 3 秒浮层提示。
4. **术语暴露**：直接写"举牌/要约收购义务/DLOM"= 违背项目文案铁律
   → **§6 双名制**，UI 只出"现象人话"。**这是必须改的一条，不是可选项。**
5. **"钱在哪"仍看不懂**：净资产 / 身价 / 市值 三数撞车
   → **顶栏只放身价**（唯一大字），公司卡只放该公司净资产/估值，市值只在「行市」出现；**三者永不同屏并列**。

## 6. 双名制对照（术语 ↔ 玩家看到的话）

| 术语（引擎/文档） | UI 显示（现象人话） |
|---|---|
| 身价 / 加权并表 | **身价** / "计上身家" |
| 举牌公告（5%） | "买到这儿，街面上都知道了" |
| 要约收购义务（30%） | "再买就得公开叫价了" |
| 特别决议（66.7%） | "卖公司/合并要**基本全体**点头" |
| DLOM 流动性折价 | "急卖要折价" |
| 保证金上调 / 强平 | "钱庄催你补钱" / "快要被平仓了" |
| 关注度 / 隐蔽度 | "外面盯着你的人" / "藏得深不深" |

## 7. 落地优先级（先做哪 3 个就能玩起来）

**第一批 = 最小可玩集团层**（呼应 `docs/19` §6「骨架先只读不交易」）
1. **总账｜集团总览**（含告急带 + 公司卡）—— 没它玩家不知道自己是谁、有什么；它同时定义一级↔二级的**唯一接口**
2. **信匣｜邮箱 + 票决｜决议投票** —— 治理闭环的**唯一入口**；把总账「⏳决议」接上，游戏立刻有"必须回来处理"的节奏
3. **估价单｜估值档案（只读）** —— "未上市靠评估、有区间、有有效期"的信息地基；没它，收购/增减持**无价可依**

**为什么不是先做「股票行/中人行」**：这两个是**动作面板**，依赖股市与估值口径先定死 ⇒ 先上动作面板＝在没价的市场上挂单。

**第二批**：往来账 → 股票行 → 行市/下单 → 中人行/谈盘 → 黄历/流水/派红
**第三批**：钱柜（授信）与 route C（贸易）

## 8. 子代理对 `docs/19 §7` 两个待定的直接回答

- **待定②「上层 UI 位置」**：选**两级导航**（集团为一级根屏，7 页签下沉为二级公司工作台），邮箱作为一级常驻入口 —— **而非"第 8 个页签"**。
- **待定③「发起门槛」**：同意 **10% 发起决议**；但 UI 上要做成**门槛距离条**（"还差 3.2% 可发起决议"）⇒ 把门槛变成**可见的目标**，而不是隐藏规则。
